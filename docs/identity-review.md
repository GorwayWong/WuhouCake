# 登录系统轻量审计记录

日期：2026-10-08。范围为本轮 identity、audit、bootstrap 认证装配、迁移、运维命令及回归测试；不包含前端、订单领域、完整渗透测试、性能压测或全量依赖漏洞扫描。

## 结论

当前实现满足已确认的首期后端需求：工号登录、首次及重置后改密、昵称维护、多岗位记录、独立超级管理员身份、账号创建/重置/归档、管理员日志查询，以及服务器上的初始化与管理员密码恢复。sample 保持不变。

发现并修正两处高置信边界问题，修正后完整测试通过。未发现剩余阻塞当前业务闭环的缺陷；轻量审计及测试不能证明不存在其他潜在 bug。

## 已修正问题

1. **退出成功被审计快照读取故障误报为失败（P2，修复风险低）**：会话已从 Redis 撤销后，读取员工审计快照的数据库异常曾使 HTTP 返回 503，阻止正常清除 Cookie。现在该步骤单独隔离，退化记录已确认的账号 ID，记录元数据故障计数，保持成功退出。[实现](../WuhouCake-identity/src/main/java/org/xaspire/WuhouCake/identity/application/service/IdentityService.java)
2. **到期前不足一秒仍签发零秒令牌（P3，修复风险低）**：临近会话截止时间时，刷新曾返回 200、expiresIn=0。现在不足一秒直接返回 401，同时拒绝不足一秒的时长配置。[配置约束](../WuhouCake-bootstrap/src/main/java/org/xaspire/WuhouCake/bootstrap/configuration/IdentityProperties.java)

两处回归用例在修正前分别复现了 503 和零秒令牌，修正后通过；退出故障用例还确认会话确已删除、旧 JWT 不可访问，以及降级审计保留账号 ID。

## 核对的业务与安全边界

- 业务岗位不会授予系统管理权限；管理员接口检查服务端超级管理员身份，个人接口不允许夹带身份变更。
- 归档保留稳定身份、工号和岗位；工号不复用；改密、重置、归档提升凭证版本，旧会话即使残留 Redis 也不可用。
- 管理员生命周期操作使用共同数据库事务锁；禁止自归档，并发归档不会移除全部有效管理员。
- Cookie 认证入口保留 CSRF；业务入口只接受 Bearer JWT；检查签名、发行方、受众、声明和有效期，数据库/Redis 认证检查故障拒绝放行。
- 初始化不覆盖既有管理员；恢复 ACTIVE 超级管理员不要求另一个管理员或现有密码，旧凭证立即失效并强制下次改密。凭证文件权限、符号链接、格式错误不泄露密码均有检查。
- 密码使用 Argon2id，临时密码只返回一次；HTTP 与常规日志不暴露密码、哈希或刷新凭证。

## 保留的既定取舍

固定随机刷新凭证最长 7 天，不轮换或检测重放；审计尽力写入，极端故障可缺失；首期不做按岗位授权、MFA 或账号恢复。它们与已确认需求一致。访问 JWT 的 15 分钟是默认配置而非硬上限，不把配置能力当作缺陷；生产建议保留默认时长。

公网部署仍需同源 HTTPS 和入口请求限流，工号失败次数计数不能替代整体入口限流。归档目前只保留账号及历史身份关联，不批量归档尚未实现的订单数据。

## 验证

`./mvnw -B clean verify -Pintegration`：87 项单元、架构及集成检查通过，零失败、零错误、零跳过。集成测试使用真实 PostgreSQL 17、Redis 7 和隔离 schema/键前缀。前轮另已验证 Java 21 非 root 容器的登录、改密、撤销及管理员恢复。

管理员设置与恢复的操作步骤见[账号运行说明](identity.md)。退出失败隔离参考 [Spring Security 的退出清理约定](https://docs.spring.io/spring-security/reference/6.5/servlet/authentication/logout.html)。

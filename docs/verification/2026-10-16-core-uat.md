## 4. 缺陷、能力缺口与环境风险

### 已确认缺陷

**F1 · P1 · 重置/归档不撤销已经建立的 SSE。**

复现：员工登录并订阅 `/api/orders/stream`，读取 ready；D 对其重置密码或归档；确认旧 `/api/me`、`/api/auth/refresh` 均为 401；D 为任意订单添加备注。旧流仍收到 `order.changed`，包含 orderId、itemId、changeType、version。两种撤销方式均在独立复现及完整集成运行中失败。未发现旧 REST 能继续读取客户详情；泄漏范围是订单活动元数据。

根因：[OrderStreamController.java:21](../../WuhouCake-order/src/main/java/org/xaspire/WuhouCake/order/adapter/web/OrderStreamController.java#L21) 只传 JWT 到期时间；[OrderStreams.java:32](../../WuhouCake-order/src/main/java/org/xaspire/WuhouCake/order/adapter/web/OrderStreams.java#L32)、57、106 行的连接/分发仅检查连接截止时间，没有员工、会话或凭证版本。源码推断窗口最多到本连接建立后 5 分钟与 JWT 到期的较早者；本轮实际证据是撤销后立即收到事件，没有等待完整窗口。

建议：连接绑定员工及会话/凭证版本；在撤销成功提交后关闭受影响连接，发送前防止撤销竞争。最小回归为 [OrderExportIT.java:395](../../WuhouCake-bootstrap/src/test/java/org/xaspire/WuhouCake/bootstrap/OrderExportIT.java#L395) 的两个参数化用例。保留失败断言，未修改生产实现。

**F2 · P2 · 正常 SSE 断开产生 ERROR 并再次尝试写 JSON。**

复现：建立流读到 ready，关闭连接，再触发订单变更/心跳；观察后端日志。E/backend.log 第 39 行起记录 `AsyncRequestNotUsableException`，继而 `HttpMessageNotWritableException: No converter ... ApiResponse ... text/event-stream`。requestId 示例 `c7305931-0a03-4307-a4c4-1cecb3b27905`，时间 `2026-10-16T01:18:59.978+08:00`。完整集成测试同样复现。

根因：[ApiErrors.java:71](../../WuhouCake-bootstrap/src/main/java/org/xaspire/WuhouCake/bootstrap/security/ApiErrors.java#L71) 把异步断连纳入通用 500 JSON 处理。影响是错误日志洪泛和排障噪声；本轮重连、业务提交均正常。建议识别已断开的异步响应，避免再写错误包络，并适当降低预期断连的日志等级。

**F3 · P3 · 账号运行文档断链。**

复现：打开根 README 第 54/86 行的账号说明或 `docs/dev-ops/admin-prod.md:8` 的账号 API 链接，目标 `docs/identity.md` 不存在。建议恢复当前接口文档或修正链接。此项不影响已启动系统的下单；没有擅自补写或改动运维文档。

未确认 P0；上述 P1 是试用阻塞。没有把测试脚本的选择器/等待条件调整记为产品缺陷。

# 客户填单、固定套餐与制作流程验证

## 范围与当前行为

依据《客户UI与功能需求梳理》的 U06、F01 及本轮确认的商品、套餐、制作和统计要求实施。截图来自本机隔离 schema 和合成演示数据；没有修改真实业务订单。不同截图使用不同合成订单展示对应状态。

| 要求 | 当前行为 |
| --- | --- |
| U06 待处理提示 | 导航显示全部客服的待处理数量，30 秒刷新；列表默认全部客服，手动刷新及处理后同步数量 |
| F01 历史未付款 | 独立快捷按钮，不限日期，忽略其余筛选，按下单时间升序；包含已取消记录，页面明确标示 |
| 收起筛选 | 订单查询默认收起高级条件，保留今日、本月及历史未付款快捷按钮 |
| 分品类录入 | 蛋糕保留尺寸、内胚、奶油、夹心等字段；面包、甜甜圈、纸杯蛋糕、饮品用名称、规格、数量及其他要求简表 |
| 固定套餐 | 客服在新建订单中保存商品清单；选择后批量带入，可编辑数量、内容和移除单品；不预置实际业务套餐 |
| 简单商品制作 | 逐项勾选；整单抹面后确认“其他”，全部完成才可通过；纯非蛋糕订单也采用同一状态流程 |
| 付款日期 | 标记已付款时由系统记录；重复标记不刷新日期；改回未付款清空日期 |
| 收款汇总 | 按 Asia/Shanghai 自然日统计，包含当日新单及历史补款，不按出货日期限制 |
| 蛋糕胚统计 | 按所选出货日、已有尺寸和胚口味累加蛋糕数量；不含取消单及已移除商品，不增加制作节点或派单 |
| 客户入口 | 提交后进入待确认区，员工保存核对结果并确认才生成正式订单；二维码无需每日重建，客户无支付或状态查询入口 |

收款金额采用订单当前约定总额，撤销付款后退出该日统计；已有已付款订单不推算历史付款日期。没有付款日期的历史记录仍显示已付款，但不计入某个自然日。手动指定付款日期暂未实现。

固定套餐只保存商品名称、品类、数量及规格，不保存客户资料、商品价格或订单总额。实际套餐内容由客服提供；修改套餐可删除旧模板后保存当前清单。订单使用独立商品副本，删除模板不会修改已创建的订单。

## 转正式订单问题排查

现场原始填单及错误响应未提供，因此不能证明当时失败的唯一原因。已确认并处理的具体问题是：前端曾允许选择后端填单模型不接受的品类，后端转换又将具体领域错误压缩为通用校验失败。现在统一五类选项，保留旧 OTHER 兼容，并传递具体的品类、数量、蛋糕尺寸、总额、归属员工及核对结果缺失错误。

确认按钮旁显示未保存／缺总额／缺归属员工的原因。真实浏览器已完成“客户提交蛋糕和面包 → 员工补金额及归属 → 保存 → 确认 → 正式订单”的流程；内部交接时间留空仍可确认。

## 轻量验证结果

- 前端 TypeScript 与 Vite 构建通过；18 个相关前端测试通过，最后针对套餐、简表和表单重跑 7 个通过。
- 订单、客户填单、查询服务单元测试及 ArchUnit 检查通过。
- 15 个不同的定向集成场景分批通过：待处理数量增减、填单确认、套餐存取删除、混合商品制作、午夜付款归属、历史未付款排序，以及受状态规则影响的原有制作／交付／回滚场景。未运行全量集成套件。
- 隔离 PostgreSQL schema 从 V1 至 V17 迁移成功；V16 新增付款时间及 OTHER_DONE，V17 新增套餐表。
- 浏览器验证了待处理徽标、简表、保存与确认、简单商品勾选门槛、付款汇总、蛋糕胚汇总、收起筛选、历史未付款及套餐编辑。
- git diff --check 通过。保留工作区已有改动，本轮未提交、推送或部署。

构建仍有现存的前端大 chunk 提示。没有为此调整打包方式或增加无关优化。

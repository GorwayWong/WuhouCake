# 套餐跨账号列表同步修复验证

日期：2026-10-25。结论：跨账号创建、修改、删除会自动刷新套餐候选，选中名称及打开中的下拉菜单能及时更新；订单草稿及已保存订单保持独立。

## 变更与边界

- 套餐变更与审计成功提交后，经现有 `/api/orders/stream` 发送 `package.changed`，仅含 packageId、version、deleted。事务回滚、旧版本冲突、幂等重试和重复删除不发通知。
- 前端取消通知前的旧列表读取和目标套餐的在途带入读取，再失效并重读各搜索、分页列表；进入录单页面、SSE ready、网络恢复和回到前台时补读。没有新增 SSE 连接或轮询。
- 重命名保留同 ID 的选择并更新显示，删除或移出筛选后清空不可用选择；删除末页唯一项时退回有效页。刷新不重建订单草稿或套餐编辑表单，取消带入时显示核对提示，迟到响应不追加旧商品。
- 回归检查发现同幂等键并发创建可能先命中名称唯一索引；已在现有事务内按创建标识加锁核实，保持同请求只创建一次、只发一次通知的契约。
- 沿用现有单实例 SSE 与工作区读取权限，断线期间的变化通过重连补读，不提供跨实例广播或事件重放。无需新增数据库迁移，继续使用 V18。

## 双账号真实浏览器验证

使用两个独立 Chrome profile，店长为普通 `STAFF/MANAGER`，员工为 `STAFF/FRONT_DESK`。后端为本轮构建，连接真实 PostgreSQL/Redis；前端 5174、后端 18081，使用独立 schema 与合成数据。

关键同步观察过程中，员工没有刷新页面或点击搜索，订单表单始终保持打开。对客户字段、日期控件、交接/归属选项、全部商品输入、普通/会员报价与整单金额做前后快照比较；另比较普通手工订单和套餐生成订单的完整 GET 详情。

| 场景 | 结果 |
| --- | --- |
| 店长改名时员工下拉框保持打开 | PASS：选中名称和菜单选项都更新，旧名称消失；本轮从保存操作到观察到更新约 163 ms，草稿快照一致 |
| 店长删除员工已选套餐 | PASS：选项自动移除、选择清空、带入按钮禁用；本轮约 191 ms，已填商品及全部表单快照一致 |
| SSE 断开期间店长修改 | PASS：恢复真实连接后补读到最新名称，连接恢复为 live，草稿不变 |
| 删除第 2 页唯一套餐 | PASS：21 个套餐减为 20 个，员工自动回到有效页，可选项完整，草稿不变 |
| 带入响应迟到期间套餐被删除 | PASS：通知取消该读取，之后释放旧响应也未追加商品，草稿及已保存订单不变 |
| 已保存订单 | PASS：普通订单及五项商品的套餐订单完整详情快照持续一致 |
| 浏览器错误 | PASS：两会话的 JavaScript 错误列表为空 |

163/191 ms 是本机本轮观测，包含 UI 自动化开销，不构成外部网络下的时延承诺。重连检查在测试页模拟前台状态、阻断后续 SSE 请求并中断当前流，恢复时重新连接真实后端；迟到检查只延迟浏览器交付已经收到的真实详情响应，没有替换业务接口返回内容。

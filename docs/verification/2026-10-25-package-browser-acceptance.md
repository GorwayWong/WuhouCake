# 套餐管理双账号浏览器验收

日期：2026-10-25。结论：店长新建、修改、删除套餐，员工带入商品，以及已有订单隔离性均通过；发现一项套餐列表名称缓存的显示问题。

## 验证环境与方式

使用 agent-browser 操作两个独立 Chrome profile：普通店长账号为 `systemRole=STAFF`、`jobRoles=[MANAGER]`，员工账号为 `STAFF/FRONT_DESK`，未依赖超级管理员资格验证套餐维护。

前端使用当前仓库代码，后端使用与 8080 业务服务相同的 JAR 构建，连接真实 PostgreSQL 17 和 Redis 7，数据库迁移到 V18。验收前端 5174、后端 18081，使用独立 schema `package_preview_01a16f6d` 和 Redis 命名空间；现有 5173/8080 服务保持运行。

套餐新建、修改、删除，以及订单填写、选择套餐、带入、修改商品和提交订单均由浏览器实际页面完成。准备合成账号使用正式身份接口；订单与套餐详情 GET 用于断言，员工越权接口仅验证拒绝结果。没有使用模拟业务 API，也未修改应用代码。

## 验收结果

| 场景 | 结果与证据 |
| --- | --- |
| 店长进入套餐管理 | PASS：普通店长账号显示管理入口并可维护；系统角色为 STAFF |
| 店长新建套餐 | PASS：新建“[验收]午后组合”，包含水果蛋糕 × 1（8 寸、动物奶油）、纸杯蛋糕 × 6（小份）；保存后列表、数量和规格正确 |
| 店长修改套餐 | PASS：修改名称为“[验收]午后组合新版”，蛋糕改为 10 寸、纸杯改为 8 个/大份，保存后新带入内容与最新详情一致 |
| 店长删除套餐 | PASS：确认删除后，管理列表为空；员工重新搜索或刷新后不再能选到该套餐 |
| 员工权限 | PASS：不显示套餐管理入口；直接访问管理页被拦截；新建、修改、删除请求均返回 HTTP 403 |
| 空白订单带入 | PASS：两项套餐商品填入后恰为两项，没有多余空白商品行，报价为空 |
| 已有商品的订单带入 | PASS：保留原有定制商品、数量、普通报价 168 元、会员报价 138 元和整单金额 499 元，套餐商品追加到末尾 |
| 连续带入同一套餐 | PASS：原有一项商品加两份套餐，共五项商品；同名商品没有合并 |
| 按本单需求修改 | PASS：将一项纸杯数量改为 9，填写客户专属祝福，套餐原始数量仍为 6；五项商品订单提交成功 |
| 套餐修改后的既有订单 | PASS：普通手工订单和使用套餐创建的订单，修改前后完整 GET 详情快照一致 |
| 套餐删除后的既有订单 | PASS：两张订单的完整详情快照仍一致；重新打开订单，五项商品、定制数量、报价及整单金额保留 |
| 已打开的商品草稿 | PASS：店长在另一浏览器修改、删除套餐后，员工已带入商品的字段及金额快照保持一致 |
| 浏览器运行错误 | PASS：两个会话的 JavaScript 错误列表均为空 |

手工对照订单在套餐变更前创建，含一项商品，金额 299 元。套餐订单含五项商品，金额 499 元，纸杯数量分别为 6 和客户修改后的 9；原有定制商品数量 2，普通/会员单价分别为 168/138 元。订单比较覆盖完整接口详情，包括版本、状态、时间、客户、交接、商品和金额。

## 发现：跨账号修改后，列表名称可能保留缓存

此问题后续已修复并完成双账号回归，见[套餐跨账号列表同步修复验证](2026-10-25-package-live-sync.md)。以下保留本次修复前的观察。

员工已打开并选中套餐时，另一浏览器的店长修改名称和商品，员工下拉框仍可显示旧名称“[验收]午后组合”。搜索或刷新后名称更新。

已补充实际验证：保持旧名称选中，点击“带入商品”，系统重新读取详情，实际带入的是最新的 10 寸、8 个和大份规格。后续删除套餐没有改动这些商品副本或已保存订单。因此本次未发现商品内容过期或历史订单被回写，但列表标签不会自动跨账号同步；本轮记录该显示问题，未修改同步策略。

## 对原有业务数据的核对

测试前后直接在 PostgreSQL 内计算各行内容摘要并按 ID 聚合，只输出数量和指纹，不读取业务联系方式到报告。结果完全一致：

| 业务表 | 前后数量 | 内容指纹比较 |
| --- | --- | --- |
| public.cake_order | 16 → 16 | 一致 |
| public.cake_order_item | 26 → 26 | 一致 |
| public.cake_order_activity | 164 → 164 | 一致 |

此核对证明本轮验收未修改原有业务订单、商品或活动；功能隔离性另由合成订单的完整前后快照比较验证。

## 收尾与边界

验收临时前后端及两个 Chrome 实例已停止，独立 schema、6 个 Redis key、合成凭证、临时密钥和浏览器 profile 已清理。业务服务继续监听 5173/8080，public 数据库保持 V18。

本轮完成桌面双账号真实浏览器验收，没有对现有业务订单做写操作，没有重新运行完整单元/集成测试套件，没有提交 Git。此前自动测试及迁移验证见[实现验证记录](2026-10-25-order-package-management.md)。

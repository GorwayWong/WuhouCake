# 订单查询明细分页验收

日期：2026-10-17。

## 行为

- 查询明细固定每页 10 条，上下均可翻页，显示总单数、当前范围和页码。
- 点击订单号或每行“查看详情”打开对应订单。通过详情左上角“返回查询结果”或浏览器后退，可在当前登录会话内恢复筛选输入、已应用条件和页码；刷新或重新登录后重置。
- 重新查询、快捷查询或统计分组筛选回到第一页。订单变化导致当前页超出范围时，自动回到有效末页；零结果显示 0 单并禁用翻页。
- 页码仅影响明细，统计与 XLSX 导出覆盖全部匹配订单。未应用的筛选输入不影响当前结果，并阻止导出。

## 验证结果

- `cd frontend && npm test`：50 项通过，含空结果、10 条分页末页范围、页码窗口及结果减少后的回退计算。
- `cd frontend && npm run build`：通过。
- Playwright + Chrome，连接独立测试后端、PostgreSQL 数据库及 Redis 命名空间，创建 23 条模拟订单；未使用真实员工或订单。
  - 三页分别为 10、10、3 条，无重复，首尾按钮状态正确，上下分页均可使用；所有明细请求为 `size=10`。
  - 查询第 2 页打开详情、进入日志、返回详情及查询，保留页码、已应用筛选和未应用输入；订单号和显式详情入口均匹配对应订单。
  - 在第 2 页下载并解析 XLSX：5 张表，订单明细 23 行；导出与查询业务筛选一致，导出未携带分页参数。
  - 修改筛选后回到第 1 页；无匹配订单时显示零结果且不能翻页。
  - 390px 手机视口可翻页，页面无横向溢出；宽表格在独立区域横向滚动。
  - 在另一请求中取消第 3 页的 3 张订单，SSE 刷新后总数为 20，自动回到第 2 页。
  - 浏览器脚本错误为 0。

后端分页接口保持现有契约，本次仅修改前端和相关说明。临时测试服务、数据库和测试密钥在验收后清理；真实本地服务及原有未提交文件保留。

# 表单控件与工作台状态筛选审查

日期：2026-10-17。范围：全站单选下拉、日期／时分输入及工作台订单状态筛选。

## 发现与处理

| 问题 | 处理 |
| --- | --- |
| 原生 `select` 和日期弹层随操作系统改变，选项大小不能由页面统一控制 | 使用 React Aria Components 的 Select、DatePicker、TimeField，统一中文和本项目配色 |
| 手机端选项与日期容易误触 | 下拉触发区和选项至少 48px 高，日历日期格为 44×44px；弹层通过组件库 Portal 和位置计算避让视口 |
| 替换控件后可能丢失键盘行为、表单禁用和错误焦点 | 保留空值与字段值映射；显式传递 disabled；错误定位聚焦可见日期段或按钮；验证方向键、Enter、Escape 与焦点恢复 |
| 工作台固定状态列表包含当前范围没有的状态，且没有制作节点 | 从未筛选的周／月历订单动态生成；同一名称与匹配函数驱动卡片和筛选，加入夹层／抹面节点 |
| 日期组件会在空的日期时间字段选日后补入 00:00 | 分开输入日期和时分，二者完整后才形成业务时刻；员工可明确输入午夜，不自动猜测 |

React Aria 同时覆盖下拉、日期、时分及可访问性，无需引入整套管理后台样式。参考 [Select](https://react-aria.adobe.com/Select)、[DatePicker](https://react-aria.adobe.com/DatePicker)。本次新增 `react-aria-components` 和 `@internationalized/date` 两个直接依赖；当前生产 JavaScript gzip 约 246 kB，分页修复时约 142 kB，增加约 104 kB，主要用于交互、日期与国际化。未改变后端接口、订单状态机或数据结构。

## 验证

- `cd frontend && npm test`：56 项通过；`npm run build`：通过。新增日期／本地时分转换、空值和异常日期、完整时刻组合、动态状态去重排序、制作节点匹配及筛选记忆测试。
- Chrome 浏览器连接本地后端，用演示员工读取订单。创建订单接口在浏览器中拦截，仅校验提交内容，不落入现有订单库。
- 动态状态与当前范围原始数据一致；夹层筛选、刷新记忆、筛选后仍可看到其他状态选项、切换范围后无效状态回到全部，均通过。
- 下拉键盘选择、空值恢复、Escape 取消和触发按钮焦点恢复通过。
- 日期选择后收起；清空必填日期阻止查询；修改日期后查询与 XLSX 导出使用同一组条件。
- 390px 手机视口：弹层不越界，选项至少 48px，日期格 44px，页面无横向溢出；已查看截图。
- 将浏览器时区设为洛杉矶，录单仍提交北京时间；仅选日期不补时刻，Enter 不意外创建订单；商品类型、员工和交接方式保持正确，写入期间控件禁用。
- 编辑资料时完整时刻回填正常；清空日期后重新选日，保留已填写的时分。取消编辑未保存。
- 浏览器脚本错误为 0。验收为 Chrome 和手机视口模拟，未进行实体 iOS Safari 测试。

状态选项仅在日历数据成功读取后校准；请求错误或读取中保留记忆条件。经营查询和导出的正式状态枚举维持原契约，不能将夹层／抹面节点提交为后台状态。

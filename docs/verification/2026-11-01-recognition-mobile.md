# 手机优先的识别填入验证

日期：2026-11-01。范围：员工新建订单的粘贴识别、字段强调、覆盖与商品替换、单次撤销，以及订购人识别别名。

## 行为

“识别并填入”直接写入合法非空值，覆盖已有内容；有效商品内容替换当前列表。疑义值以“请核对”提醒，不增加确认步骤或提交门槛。正式表单显示带入来源，手工修改后移除对应标记；撤销保留后续手工修改和主动删除结果。日期和时刻作为整体撤销。可选 AI 补充只写入本次补充字段，保留原有主动授权。

## 轻量验证结果

- `node --experimental-strip-types --test tests/recognition.test.ts`：13 项通过，包含覆盖、缺失字段、疑义值、无效值、商品替换、重复识别、撤销、商品删除、日期时间一致性、标记跟随稳定商品 key、AI 补充和迟到响应取消。
- `node node_modules/typescript/bin/tsc --noEmit`：通过。
- Java 21 执行 `./mvnw -pl WuhouCake-order -am -Dtest=OrderRecognitionTest,ModuleArchitectureTest -Dsurefire.failIfNoSpecifiedTests=false test`：37 项订单识别测试及依赖模块、订单模块 ArchUnit 检查通过。别名覆盖订购人姓名、订购人、客户订购人、客户下单人和下单人。
- 临时浏览器预览在 375px、390px、1280px 下分别检查单商品和多商品，共 6 组流程：字段覆盖、列表替换、强调色、疑义标记、自动收起、焦点释放、手工改值后清除标记及撤销均通过，无横向溢出。额外模拟识别失败，原文及表单内容保留。
- 浏览器预览使用真实 React 组件和模拟 API 数据，不创建订单、不外发原文至 AI。真实规则解析由上述 Java 定向测试覆盖；没有运行全量集成或真实手机设备测试。

# 全部口述需求最终审查与回归

日期：2026-10-17。审查对象为当前工作区，承接[八项审计修复](2026-10-17-workflow-fixes.md)与[协作、识别和经营报表验收](2026-10-17-collaboration-reporting.md)。按用户已确认范围，本阶段只做员工业绩汇总；纸单照片仅作为字段和单据参考。

## 本轮发现并修复的问题

| 问题 | 修复与验证 |
| --- | --- |
| 创建已提交但响应丢失，再次提交可能重复建单 | 网页每份录单草稿使用独立 Idempotency-Key。相同员工、标识和内容的并发/重试只提交一次，返回原单最新详情；标识与不同内容冲突返回 409。结果未知时保留并锁定原提交，可手动重试确认。标识预约、订单、商品和创建活动失败一并回滚。 |
| 防重复记录可能与交叉代录的员工行锁形成死锁 | 专门让甲替乙、乙替甲同时录单，在旧锁关系下复现 503；调整提交记录的员工标识外键锁关系后，两笔均成功。提交标识仍按认证操作者隔离，账号保留策略使用归档。 |
| 员工创建、改名、密码重置和归档等业务变更可能成功却没有审计 | 账号业务变更与审计同事务提交，包含适用的前后姓名、岗位、状态、凭证版本等非敏感快照。故障注入验证业务及版本回滚，失败的归档/重置不撤销仍有效的会话。登录/退出的独立审计故障处理保持，不阻止退出。 |
| 识别出的尺寸可能超过最终写入精度，或把符号/范围/高度/配件人数截成有效值 | 识别、候选应用与写入统一为正数、最多两位小数和九位整数。负号、范围、尺寸高度、非整数数量及餐具人数等不自动变成本单有效规格/数量；保留原文并提示核对。“十二个”不会被截成“二个”。 |
| 混合标签或不完整联系人文本漏掉已明确字段 | 姓名/电话/地址可以独立形成候选，提取首个标签前的收件信息；姓名与不完整地址仍要求人工确认。回归无地址、只有地址、自由文本、混合标签、多个候选及商家客服排除。 |
| 点击更新提示后取消离开，提示仍提前消失 | 所点订单在当前页面成功打开后才标为已读；取消导航、保留草稿或在新标签打开不清除当前页提示。浏览器实际取消/接受确认框验证。 |
| 日历首次请求失败后仍显示空日期格 | 没有成功数据时不渲染空日历；有缓存但刷新失败时明确标注旧内容并提供重试。浏览器模拟首次 503、缓存刷新失败与恢复。 |

防重复标识只在当前标签页的草稿生命周期内保存。刷新、关闭或确认放弃后的新录单使用新标识，应先核对工作台。未携带 Idempotency-Key 的其他 API 调用每次创建新单；不同员工或不同草稿也可以合法创建内容相同的订单。

## 全部需求对照

| 口述需求 | 最终结果 |
| --- | --- |
| 前台录单，订单可查询 | 可手动填写、规则识别后补填，并从日历、详情、经营筛选查询。 |
| 多位师傅单独或协作制作，多商品不逐件更新进度 | 夹层、抹面、制作完成及交付按整单手动记录；不自动确认未记录节点，不按小产品逐件推进。 |
| 付款与客户收货由前台手动确认，配送员不进入系统 | 付款独立手动更正；配送/自提由员工操作，制作完成不自动确认收货。 |
| 多人修改正确，保留协作记录和合适粒度日志 | 订单共用 expectedVersion；陈旧保存拒绝并保留草稿，人工核对后继续。修改前后值与真实操作者同事务留痕；备注/图片同版本仍刷新。 |
| 员工收到信息更新 | 事务提交后 SSE 推送，断线恢复重新读取；站内提示本次在线期间最近 20 张订单，可打开详情，完整历史以持久化日志为准。 |
| 员工账号增删改查 | 管理员创建、查询、修改姓名/岗位、重置密码及归档；固定工号，归档保留历史身份与归属。业务变更审计失败回滚。 |
| 下单业绩员工与创建员工分别记录 | 可选在职员工；创建人来自认证上下文且不改写，归属更改记录原值和新值。旧单未归属保持“未归属”，员工改名/归档不拆分账号业绩。 |
| 蛋糕默认原味内胚、芒果夹馅 | 输入框默认真实文字，写入清空与旧数据读取均兜底；明确指定优先，非蛋糕不套用蛋糕默认。 |
| 尺寸用于可靠筛选统计 | 新写入只收正数、最多两位小数，规范化保存；8、8.0 合并。旧异常值可读、进入待核对组，不引发数值转换错误。 |
| 时间段内尺寸和员工业绩统计 | 全范围汇总商品 quantity，尺寸组内订单去重；混合订单金额只算一次，未填金额独立计数。约定金额及手动付款标记不等于实收或提成。 |
| 组合筛选与导出一致 | 日期、状态、付款、交接、尺寸、员工和关键词共用条件；默认排除取消单，可明确包含/只选取消。分页只影响列表；五表导出与汇总使用可重复读快照。 |
| 日历默认当天出货全部订单，筛选有记忆 | 首次为当天、全部状态和付款；两个筛选按账号保存，异常存储回退全部；含完成/取消订单。请求失败不伪装无订单。 |
| 查询、查看和导出非必要不记日志 | 不新增订单业务活动、不改版本、不发变更推送；历史导出日志仍可读。 |
| 示例预订单和纸单参考 | 已验证模板字段、空值、默认值、会员手机、祝福语和其他要求；订购须知、运费、可选配料及餐具尺寸不成为本单事实。照片 OCR 不在本阶段范围。 |

## 回归验证

最终结果：255 项 Java 单元/ArchUnit、81 项基础设施/HTTP 集成测试、43 项前端测试全部通过，共 379 项；失败、错误、跳过均为 0，TypeScript/Vite 构建通过。最终浏览器会话未处理错误为 0。

- 后端执行 `rtk proxy ./mvnw -Pintegration verify -q`，包括单元、ArchUnit、真实 PostgreSQL/Redis、HTTP、事务和 SSE 回归。
- 前端执行 `rtk proxy npm test`、`rtk proxy npm run build`。
- 新增数据库用例覆盖：相同标识并发重试、不同内容冲突、不同员工标识隔离、创建失败回滚预约、归属员工归档后重放原提交、账号业务审计故障回滚、交叉代录的锁竞争。
- 导出快照用例在读取总额后暂停导出，由另一位员工把商品数量 2 改为 3、约定金额 520 改为 600，再继续导出。五表仍一致保留原快照，之后的新查询显示更新后的值。
- 浏览器实际模拟创建事务成功后丢弃响应；两次请求内容和标识相同，重试返回原订单。数据库核验仅一张订单、一条创建活动、一组商品和一个完成标识。
- 浏览器验证取消跳转后草稿与未读保留，接受跳转后提示清除；首次日历失败不显示空格、旧缓存失败有标识且可恢复；混合联系人与高精度尺寸异常提示可见。
- SSE 回归读取器修正了将合法心跳注释帧误判为业务事件的问题；继续保留对真实订单事件、撤销后断流和回滚后保持会话的断言，整套回归重新通过。
- 复验经营分组、尺寸明细下钻、日期口径切换、真实五表 XLSX 下载及 390×844 视口布局。下载 OpenXML 核对分组、订单/商品行数、数量、金额及无公式内容；测试未使用真实客户信息或外部识别服务。

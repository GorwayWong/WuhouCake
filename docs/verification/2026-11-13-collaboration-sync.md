# 工作台协作同步最小修复验证

基线：`7134098` 加实施前已有的本地未提交改动。日期：2026-11-13。本轮修改订单查询同步、查询轮询默认值、客户填单分页及只读事务、通知提示排序；未新增依赖或数据库迁移。

## 行为

- 订单事件、ready 和恢复补读先取消对应在途查询，再失效重取；删除缓存标记在取消完成后应用。迟到的首读不能覆盖新数据，失败补读不能恢复已删除订单的可写状态。
- calendar、workbench、management-orders、order 的活动且启用的查询默认前台每 30 秒补读，后台停止周期请求；客户填单和制作提醒保留原周期。通知及查询错误仍沿用原有提示。
- 同订单低版本通知不能替换已有高版本通知或其时间；同版本备注、图片仍触发刷新。
- 填单 search/detail 使用方法级只读可重复读；search 先计数并限制页码，再读取有效页。前端跟随响应页码，保留筛选及视图记忆，只有总数为零显示队列空态。

- 服务端返回有效页后，前端同步页码；非零总数的异常空页保留“返回第一页”。

首读和通知排序测试在修复前失败；分页边界单元测试及列表/详情并发快照集成测试在修复前失败。修复后上述测试均通过。

## 浏览器复跑

在 frontend 启动开发服务器后，设置 `PLAYWRIGHT_MODULE` 指向本机 Playwright 模块；默认 Chrome，默认来源 `http://127.0.0.1:5197`，可用 `DRAFT_TEST_URL` 覆盖。

```sh
node --test --test-concurrency=1 +  tests/collaboration.browser.mjs +  tests/orderDetail.browser.mjs +  tests/orderDraft.browser.mjs +  tests/calendarCards.browser.mjs +  tests/packageConflict.browser.mjs +  tests/productionQuery.browser.mjs +  tests/managementFilters.browser.mjs
```

浏览器使用合成 API；补读测试推进浏览器时钟验证调度周期，后台场景模拟 visibilitychange。既有待制作回归覆盖双页 SSE 迁日、完成和取消；草稿回归覆盖退出/切换账号、恢复及未知提交结果；套餐回归覆盖双人冲突和图片合并。数据库并发由真实 PostgreSQL 集成测试独立验证。

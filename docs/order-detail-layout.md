# 订单详情中的下单要求与工作沟通

客户填单的“其他要求”按商品保存在 `items[].attributes.requirements` 中。确认接单后，该字段随审核后的商品资料进入正式订单；详情读取正式订单当前值，不读取原始填单旧快照，也不使用工作过程的 `NOTE` 记录作为下单备注。历史 `otherRequirements` 在缺少规范字段时作为读取来源；规范字段已清空时显示“无”，不恢复旧内容。

前台业务详情按以下顺序展示：

1. 顶部订单状态、制作与交付进度以及前进、后退操作保留。
2. “订单信息”首先展示商品切换及编辑资料入口。名称／下单方式、取货时间／出品时间、客户／电话为三行两列，手机端也保持两列；随后地址、特殊要求、图片、下单时间各占整行。长文本自动换行，电话支持拨号。
3. 名称、特殊要求和图片跟随当前商品切换；特殊要求读取正式订单当前商品的要求，未填写显示“无”。图片继续支持预览、上传队列、移除及历史图片。下单时间读取整单 `createdAt`。
4. 下单时间之后直接展示当前商品资料：商品名称独占整行，数量／规格两列；蛋糕的内胚／夹馅／奶油三列，非蛋糕的价格／会员价两列，手机端保持相同列数。蛋糕规格读取尺寸、内胚读取蛋糕胚字段，非蛋糕读取自身规格。蛋糕继续只显示整单约定金额。保留商品编辑、添加、移除和底部切换，资料与上方图片及特殊要求使用同一商品选择。
5. 商品资料之后是金额与付款，再是默认折叠的工作备注与沟通，支持整单及商品对象。付款作用于整单，不随商品切换改变。
6. 工作备注之后的“补充资料”默认收起，保留业绩归属、会员手机、订购人、交接方式、商品备齐、当前商品祝福语、历史规格及其他未展示属性。最近商品备注保留在这里。导出及操作记录、取消、删除等入口继续位于下方。制作岗位保持原有详情布局及数据权限。

“下单方式”是独立整单字段 `orderingMethod`，与配送／自提、员工归属和客户填单来源分别保存。员工新建及编辑资料可选“下单人、小程序、到店、客服号”，或选“其他”填写最多 80 字符的具体文字；首尾空白去除、未填写保存为 `null`。历史自定义值显示为“其他＋原值”，不自动分类。“下单人”是固定渠道名称，扫码填单不自动归为小程序。新建草稿保留实际文字和“其他”选择状态，旧草稿和旧客户端可省略；选择状态不提交到后端。`POST /api/orders` 接受顶层字段，`PATCH /api/orders/{id}/information` 通过 `changes.orderingMethod` 更新，订单详情按业务详情权限返回。修改沿用版本校验和资料变更审计。复用已有可空列，无新迁移或历史回填。查询与导出筛选见[订单查询筛选](order-query-filters.md)。

完整操作记录与金额继续遵循现有数据权限，制作岗位不会因此获得客户、金额或下单资料读取权限。工作备注仍使用只返回 `NOTE` 的独立接口。

前台的取货时间与出品时间移入订单信息，制作岗位的制作摘要继续按左右两列展示，包括手机端；每列标签在上、时间在下，窄屏允许日期与时刻分行。取货时刻缺失时保留日期并显示“时刻待定”，出品时间缺失时显示“待定”。订单状态与付款标签显示在订单标题旁，摘要中不重复展示状态与配送方式；制作按钮和进度条保留。

详情页通过顶部“日历工作台”返回日历，不再单独显示“返回工作台”。从订单查询或付款列表进入时，分别保留“返回查询结果”或“返回付款订单列表”，加载失败时也遵循相同规则；导航继续使用现有未保存编辑保护。

状态区按当前节点提供前进和后退按钮，并明确标注目标；进度条不支持任意跳转。每次后退或恢复取消单先弹窗确认目标及对商品勾选的影响，无需填写原因。制作、交付及已完成均可相邻后退；待制作没有上一节点，已完成没有下一节点。已取消显示“恢复至待制作”，须同时具备取消和制作权限。普通后退保留勾选，退回待制作或恢复取消单才重置。向前确认其他及制作完成继续校验全部商品已勾选，付款与历史记录不随状态移动改变。

订单查询列表保留订单号与“查看详情”两个单笔详情入口，返回列表时保留原查询条件和页码。列表强化出货日期、客户电话及商品品类识别；品类读取订单中全部未移除商品，去重排序，不从商品名称猜测，也不随尺寸筛选丢失其他品类。API 明细行增加 `productTypes` 数组，导出表格列维持原契约。其他列表字段及最终组合尚未定案，不新增可配置列或额外业务字段。

验证包括下单要求与工作备注分离、空值与多商品、修改后详情显示最新值、修改人可追溯、混合品类订单、详情跳转及列表状态保留，以及普通员工和制作岗位的桌面与手机布局。

# 订单详情中的下单要求与工作沟通

客户填单的“其他要求”按商品保存在 `items[].attributes.requirements` 中。确认接单后，该字段随审核后的商品资料进入正式订单；详情读取正式订单当前值，不读取原始填单旧快照，也不使用工作过程的 `NOTE` 记录作为下单备注。历史 `otherRequirements` 在缺少规范字段时作为读取来源；规范字段已清空时显示“无”，不恢复旧内容。

前台业务详情按以下顺序展示：

1. 顶部订单状态、制作与交付进度以及前进、后退操作保留。
2. “订单信息”首先展示商品切换及编辑资料入口。名称／下单方式、取货时间／出品时间、客户／电话为三行两列，手机端也保持两列；随后地址、特殊要求、图片、下单时间各占整行。长文本自动换行，电话支持拨号。
3. 名称、特殊要求和图片跟随当前商品切换；特殊要求读取正式订单当前商品的要求，未填写显示“无”。图片继续支持预览、上传队列、移除及历史图片。下单时间读取整单 `createdAt`。
4. 下单时间之后直接展示当前商品资料：商品名称独占整行，数量／规格两列；蛋糕的内胚／夹馅／奶油三列，非蛋糕的价格／会员价两列，手机端保持相同列数。蛋糕规格读取尺寸、内胚读取蛋糕胚字段，非蛋糕读取自身规格。蛋糕继续只显示整单约定金额。保留商品编辑、添加、移除和底部切换，资料与上方图片及特殊要求使用同一商品选择。
5. 商品资料之后是金额与付款，再是默认折叠的工作备注与沟通，支持整单及商品对象。付款作用于整单，不随商品切换改变。
6. 工作备注之后的“补充资料”默认收起，保留业绩归属、会员手机、订购人、交接方式、商品备齐、当前商品祝福语、历史规格及其他未展示属性。最近商品备注保留在这里。导出及操作记录、取消、删除等入口继续位于下方。

“下单方式”是独立整单字段 `orderingMethod`，与配送／自提、员工归属和客户填单来源分别保存。员工新建及编辑资料可选“老板、小程序、到店、客服号”，或选“其他”填写最多 80 字符的具体文字；首尾空白去除、未填写保存为 `null`。历史自定义值显示为“其他＋原值”，不自动分类。历史下单方式“下单人”保留原文，按自定义值编辑和筛选，不自动改成“老板”；订购人姓名字段独立保留。扫码填单不自动归为小程序。新建草稿保留实际文字和“其他”选择状态，旧草稿和旧客户端可省略；选择状态不提交到后端。`POST /api/orders` 接受顶层字段，`PATCH /api/orders/{id}/information` 通过 `changes.orderingMethod` 更新，订单详情按业务详情或下单资料读取权限返回。修改沿用版本校验和资料变更审计。复用已有可空列，无新迁移或历史回填。查询与导出筛选见[订单查询筛选](order-query-filters.md)。

员工录单草稿的“放弃并新建”和“放弃草稿”在当前界面内二次确认，不调用浏览器原生确认框。删除成功后初始化新草稿；删除失败保留原内容，并在确认区提供“重试删除”和“返回”。跨标签页冲突禁止删除，需重新载入核对。放弃本机草稿不会撤销已创建订单，未上传图片不再随新草稿提交。旧草稿图片清理失败单独提示，不影响新草稿保存状态。关闭恢复弹窗返回工作台并保留草稿。

师傅详情先展示六节点、下一步操作和商品备齐清单。手机端按四道工序和两个交接节点分两行显示，当前节点用黄色与“当前”标识。订单信息随选中商品展示名称、出品时间、尺寸、数量、夹馅、奶油、祝福语、特殊要求和图片。非蛋糕用规格替代尺寸，整单出品时间在切换商品时保持一致。图片之后显示订购人姓名、下单渠道和实际交接方式，随后是工作备注与沟通。仅对具备相应权限的员工显示手机号和下单资料。工作备注仍使用只返回 `NOTE` 的独立接口。

详情页通过顶部“日历工作台”返回日历，不再单独显示“返回工作台”。从订单查询或付款列表进入时，分别保留“返回查询结果”或“返回付款订单列表”，加载失败时也遵循相同规则；导航继续使用现有未保存编辑保护。

状态区按当前节点提供前进和后退按钮。回退或恢复取消单需确认目标与勾选影响。普通回退保留勾选，退回出胚或恢复取消单时重置。完成装饰时校验全部有效商品已勾选。配送和自提共用待配送与已配送节点，根据实际交接方式显示「确认送达」或「确认自提」。

订单查询列表保留订单号与“查看详情”两个单笔详情入口，返回列表时保留原查询条件和页码。列表强化出货日期、客户电话及商品品类识别；品类读取订单中全部未移除商品，去重排序，不从商品名称猜测，也不随尺寸筛选丢失其他品类。API 明细行增加 `productTypes` 数组，导出表格列维持原契约。其他列表字段及最终组合尚未定案，不新增可配置列或额外业务字段。

验证包括下单要求与工作备注分离、空值与多商品、修改后详情显示最新值、修改人可追溯、混合品类订单、详情跳转及列表状态保留，以及普通员工和制作岗位的桌面与手机布局。

员工录单页顶部将草稿保存状态与放弃入口合为紧凑工具栏，放弃确认在其下方展开。商品信息中的“使用套餐”默认收起，展开才查询，收起保留本次搜索与选择，带入过程中禁止收起或重复带入；刷新或新开订单后恢复收起。套餐商品仍追加到当前订单，不覆盖已填写商品或自动填写订单金额。

取货、出品及业务列表日期按上海时区的当前年份显示：今年使用 `MM/DD` 或 `MM/DD HH:mm`，其他年份保留 `YYYY/`。日期控件的按钮遵循同样规则，日历月份标题和无障碍标签保留完整年份。接口、草稿、查询参数、排序和数据库保持完整日期值；操作日志、草稿保存时间、导出文件及其文件名保留年份。仅有日期的订单继续标记“时刻待定”。前厅详情取货／出品时间为 20px 加粗，电话和地址为 18px，长地址自然换行，电话保留拨号链接。

共享蛋糕编辑表单将蛋糕胚和奶油并排，夹馅独占一行并使用可纵向扩展的两行文本框。员工新建、编辑、套餐维护及客户填写／核对采用一致排布，字段键和默认口味规则保持不变，错误定位遵循视觉顺序。非蛋糕规格不变。

整单金额区显示“原价（元）”“会员价（元）”与支付方式，两种报价与商品单价分别保存。会员价非空时作为成交金额（包括 0），否则采用原价；两项均空为未报价。成交金额由服务端计算，付款、欠款及经营汇总继续读取同一成交金额。旧订单未记录双报价时沿用原整单金额展示，不回填报价或推断支付渠道。

支付方式为银联、扣卡、对公转账、客服微信、现金、未付。新录单默认未付；选择前五项时在创建事务内登记已付款和服务器付款时间，仅记录，不调用支付或扣卡系统。已付款订单更正方式保留付款时间，改回未付清除付款时间，再付款重新记录。详情页更正金额保留付款状态；更正支付方式使用订单版本校验并记录审计。历史已付款但无支付方式时显示“已付款（方式未记录）”。草稿保留报价和支付方式，提交结果未知时沿用原载荷和幂等标识，旧草稿及旧客户端省略新字段仍可使用。

## 编辑图片与页面更新保护

修改资料、金额或已有商品时，新选图片按账号、订单与编辑会话暂存到本机，不立即上传。保存修改成功后转入现有幂等图片队列；只选图也可保存，不发送空资料修改。本会话未选图片时，取消编辑不访问图片存储；有新选图片时先清理，清理失败保留界面并允许重试；不影响已保存图片及其他队列。新增商品尚未保存、商品已移除或订单不可写时不能添加图片。编辑期间不能删除服务器已有图片。

资料保存失败、结果未知或版本冲突时不自动上传；重载后仅在原账号、原标签页恢复暂存图片及预期文件清单，允许继续编辑恢复，或核对最新资料后仅继续上传。其他标签页及无法确认归属的旧暂存不展示或接管。复制标签页通过 Web Locks 检查会话占用；不支持 Web Locks 的浏览器使用新会话，保留旧文件但不恢复。保存前及转队列事务内均校验预期图片，文件缺失必须重新选择或明确移除，不能按空队列完成。资料已保存但图片失败时分别提示并仅重试失败图片，不重复提交资料。图片不递增订单版本，图片刷新不清空未保存字段。保存、清理及上传期间禁止离开或重复操作。

日历按取货日期显示。未知状态进入“状态待更新”分组并保留订单卡片，详情只读，不猜测状态转换。员工页面在生产环境加载、重新可见和连接重建时检查入口脚本版本，发现更新只提示保存后刷新。有未保存编辑、在途操作或不安全草稿时禁用刷新按钮；检查失败不影响现有工作。此检查不能修补首次发布前已打开的旧页面，首次上线须提醒用户保存并刷新一次。

主动退出登录时先清理草稿记录并保留快照，确认退出成功后再按原草稿标识清理图片。退出失败恢复草稿且保留图片；本机恢复写入失败时保留内存内容并提示不要关闭页面。退出成功后的图片清理失败在登录页提示，不回滚退出。

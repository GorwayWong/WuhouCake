## 保留的业务规则

- 一个订单是统一制作和交接单元，不支持部分商品先交付。商品支持逐项勾选完成，但没有独立的夹层、抹面或交接流程。
- 制作完成只表示备齐，不能自动确认客户收到。配送为待配送→配送中→完成，自提另行确认。
- 所有订单均须依次开始制作、完成夹层、完成抹面、确认“其他”，再完成整单制作，不能跳过节点。所有有效商品（含主蛋糕）逐项勾选完成后才能确认“其他”，完成整单制作时仍校验全部商品已完成。取消任一商品的完成勾选后，已确认的“其他”退回抹面完成。
- 制作与交付支持逐节点回退，已完成订单也可回退；待配送/待自提先退回“其他已确认”，再依次退回已抹面、已夹层、生胚中、待制作。普通回退保留商品勾选，退至待制作时清空整单制作阶段，并重置全部有效商品为未开始。已取消订单可恢复至待制作，执行同样重置，保留原订单号、业务资料、付款及历史活动。
- 付款与制作互不阻断。总额是与客户约定值，不按数量或商品报价自动重算；空金额与 0 元不同。
- 员工下单页一次编辑一张商品卡片，手机和桌面均可通过上下两组左右按钮切换，切换保留输入和字段提示。新增、套餐带入、识别替换、删除及撤销按稳定商品 key 更新当前卡片，提交错误可定位到尚未显示的商品。金额区分别提示全部商品的普通单价×数量、会员单价×数量合计；缺价时显示已填写部分和“有商品未填价格”，全部缺价显示“—”，明确零元正常计入。编辑中数量或价格无效的项暂不计入并提示未完成；计算使用整数分，不自动改写订单约定总金额。
- 订单详情的“全部商品”沿用接口顺序，一次显示一张商品卡片，手机和桌面均支持上下左右按钮切换。刷新按 itemId 保留当前商品，当前项移除后显示邻项，新增成功后定位新增项；编辑或新增期间禁用切换，协作移除编辑对象时仍保留原草稿和冲突提示。商品备齐清单继续完整展示，岗位字段及价格可见范围保持现有权限规则；未新增原始录入顺序的持久化保证。
- buyerName 在界面显示为订购人姓名，是向门店订购商品的客户，可留空；creditedEmployee 是独立的下单员工归属，用于员工业绩，创建/操作员工由服务器认证上下文决定。新单未传归属时使用当前员工，历史未归属不推定创建者；归档保留身份和昵称快照。
- 粘贴录单点击“识别并填入”后，合法非空值覆盖已有字段；有有效商品内容时替换商品列表，没有商品内容则保留原列表。未提供字段保留原值，未手改的初始收货日期仍受防误用校验。带入值以强调色和“已带入／请核对”标记，疑义提醒不增加提交门槛；手动修改后移除该字段标记。撤销本次填入恢复覆盖值和原商品，保留后续手工修改、新增商品及主动删除结果。可选 AI 补充经授权后只填入本次补充字段，不重放规则或替换商品；未识别原文折叠保留。订购人识别兼容订购人姓名、订购人、客户订购人、客户下单人及下单人。
- 时间统一为客户收货时间（requestedReceiveDate/requestedReceiveAt）、到店取货时间（plannedHandoffAt）、计划出品时间（plannedFinishAt）。员工新建与改期允许仅填客户收货日期，时刻待定，不补零点；客户自助填单仍需完整时间。客户填单核对可补到店取货与计划出品时间。日历按客户收货日期归日，不从其他时间推算。
- 工作台左侧时间轴展示半小时分组时段：普通视图按到店取货时间显示“取货时段”，制作视图按计划出品时间显示“出品时段”，准确时间见订单卡片。仅展示有订单的时段，轴线连接分组，不表示时间间隔比例；未安排时间显示取货／出品待定。时段不在当前选定日期时显示日期，跨午夜的结束时间注明次日；周历和月历展开区保持一致。
- 工作台订单卡片单独标红客户期望收货时间；仅填写收货日期时显示该日期及“时刻待定”，不从取货或出品时间推算。
- 商品类型统一为蛋糕 CAKE、茶歇 TEA_BREAK、饼干 COOKIE、小吃 SNACK、饮品 DRINK、现货面包甜点 READY_BAKERY。V22 将 DONUT/CUPCAKE/OTHER 归茶歇、BREAD 归现货面包甜点；原始客户填单和活动日志不改写，已有额外规格保留。只有蛋糕展示尺寸、内胚、奶油、夹馅、祝福语；其他商品仅填写名称、类型、数量及可选规格、特殊要求，员工仍可填报价。所有类型均保留现有整单夹层、抹面等状态。
- 奶油界面使用 attributes.flavor，内胚为 base，夹馅为 filling。蛋糕创建、追加、清空和缺失值读取统一使用原味内胚/芒果夹馅；显式选择优先，非蛋糕不套默认，读取兜底不写库。蛋糕尺寸只接受正数、最多两位小数、整数部分最多九位，保存为无单位数值文本；旧异常尺寸仍可读取。
- 工作台默认周历，过去日期有未完成交付的订单时，周历与月历均以红色及未完成数量提醒，不受筛选影响；完成、取消、删除不计入。订单优先展示未完成，再展示完成／取消，组内按取货时间排序；每日统计及客户填单二维码管理默认折叠。详情顶部集中制作摘要、关键时间、商品备齐勾选、有效特殊要求及参考图入口，详细资料继续保留。
- 日历首次为今天、全部状态和全部付款；按员工保存两个筛选偏好，损坏时回退全部。订单状态选项来自当前周／月原始订单，包含已夹层、已抹面、其他已确认，和卡片状态一致；成功读取后所选状态不存在时回到全部。单日列表包含完成/取消订单，筛选后再显示。
- 经营查询默认按本月录单日期（北京时间）查询，预约收货日期在未来的订单也包含；日期快捷查询仅保留今天录入，其他范围手动选择。查询/统计汇总导出最多 366 天，默认排除取消单（可明确包含或仅选取消），始终排除已删除订单；逐单 ZIP 使用完整已应用条件，最多 100 单、256 MiB。尺寸筛选累加匹配蛋糕 quantity，金额仍为整单约定金额，按手动付款标记分列、缺金额单独计数，不等于实收或提成结算。员工按账号合并、未归属独立保留。经营导出最多 10,000 单、50,000 行商品，不含图片，不静默截断。
- 查询与导出不新增业务日志。实际订单变化仍同事务留痕，历史 ORDER_EXPORTED 记录继续可读。
- 查询明细每页固定 10 条，订单号及“查看详情”进入详情；当前登录会话内返回查询保留筛选及页码。统计和导出始终覆盖全部匹配结果。
- 商品至少保留一件，移除保留历史。每件商品只展示自己的最近三条备注；详情备注区预览最近三条整单/商品备注，完整备注与操作日志在独立记录页分页查询，左上角返回详情。月历的日期及订单卡片进入当天工作台。
- 店长、前厅主管和前厅店员可查完整业务资料、经营统计、导出及已删除记录；删除订单仅店长可执行；裱花主管、裱花师和烘焙师查看制作资料、客户手机号及所需时间，不能读取金额、完整客户信息或已删除订单。兼任岗位取并集，店长同时具有 SUPER_ADMIN，可管理员工并读取身份审计。
- 当前部署约定为单业务后端实例；SSE 没有跨实例广播或持久化重放，断线后通过 REST 补齐。

这些规则替代旧开发计划中的逐商品制作、两步录单、虚构独立任务聚合等草案。没有为旧计划预留通用工作流、支付、配送或制作任务模块。

## 尚未实现或尚待明确接受

| 项目 | 当前事实 |
| --- | --- |
| 独立身份审计页面 | 员工资料改动保留前后值，身份审计可经管理员 API 查询；无独立审计页面 |
| 地址真实性 | 支持标签与常见无标签收件信息提取；不进行地理编码、完整行政区划纠错或配送可达性校验，歧义仍需人工核对 |
| 图片 OCR | 当前只做文本识别；不支持截图或手抄单 OCR、HEIC 上传 |
| 支付/配送集成 | 无支付渠道、流水、退款、第三方配送调度；记录付款方式文本不能自动标已付款 |
| 部分交付、多门店、独立排产 | 当前未实现，不列为已有功能回归失败 |
| 真实语料与生产环境验证 | 少量合成模型调用已验证；真实客户语料效果、实际账单、代理/TLS、容量及长期运行仍有未验证项 |

该表保留旧资料中仍有意义的边界与缺口，不承诺实施日期。发现新的业务需求时先确认范围，不能以旧 Slice 顺序或过时数据库草图直接实施。

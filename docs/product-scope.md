# 当前业务范围与缺口

本页依据现有代码与验收记录维护当前边界，不是新功能承诺。详细字段和路由以[订单契约](../WuhouCake-order/README.md)、[账号契约](identity.md)为准；测试结果与未执行项见[验证摘要](../frontend/verification.md)。

## 已实现

| 范围 | 当前能力 |
| --- | --- |
| 员工 | 固定工号、多个岗位、独立系统权限、首次改密、管理员重置/归档、审计 |
| 订单 | 一个 Order 聚合管理多个有效商品；独立客户资料、收货日期、交接计划、商品报价和约定总额 |
| 制作 | 整单开始、可选夹层/抹面记录、完成制作、待交接重新制作 |
| 交付 | 整单配送或自提、手工确认送达/取货、带原因取消 |
| 付款 | PAID/UNPAID 人工双向纠正，有前后值历史 |
| 协作 | 乐观锁、稳定 itemId、软移除、整单/商品备注、提交后 SSE |
| 文件 | JPG/PNG 参考图、认证预览、软移除、单单 XLSX、筛选 ZIP |
| 录单辅助 | 文本规则候选、人工核对、冲突保留、撤销，可选且默认关闭的百炼语义补充 |
| 前端 | 登录、工作台周/月历、录单、资料/商品编辑、制作交付操作、图片及导出 |

## 保留的业务规则

- 一个订单是统一制作和交接单元，不支持部分商品先交付。OrderItem 的保留制作字段不表示存在可独立操作的商品工作流。
- 制作完成只表示备齐，不能自动确认客户收到。配送为待配送→配送中→完成，自提另行确认。
- 夹层与抹面是可选记录；可跳过并直接完成制作，界面显示未记录。重新制作是待配送/待自提后的明确操作。
- 付款与制作互不阻断。总额是与客户约定值，不按数量或商品报价自动重算；空金额与 0 元不同。
- buyerName 是客户侧下单人，创建/操作员工由服务器认证上下文决定；电话不代表会员资格。
- 奶油界面使用 attributes.flavor，内胚为 base，夹馅为 filling。录单表单和识别候选中的蛋糕默认原味内胚、芒果夹馅，显式选择优先；非蛋糕不套默认。直接调用正式 API 时，未提供的规格保持空对象，不自动补这两项。
- 商品至少保留一件，移除保留历史。每件商品只展示自己的最近三条备注，整单备注不混入。
- 当前按门店共享订单读取；岗位是工作职责，SUPER_ADMIN 才是账号管理权限。普通员工目前也能导出，不宣称已做管理员专属导出隔离。
- 当前部署约定为单业务后端实例；SSE 没有跨实例广播或持久化重放，断线后通过 REST 补齐。

这些规则替代旧开发计划中的逐商品制作、两步录单、虚构独立任务聚合等草案。没有为旧计划预留通用工作流、支付、配送或制作任务模块。

## 尚未实现或尚待明确接受

| 项目 | 当前事实 |
| --- | --- |
| 专门订单号搜索 | 工作台按日期显示订单号；没有独立订单号搜索入口 |
| 管理员页面 | 管理账号和身份审计有 API；当前 React 没有管理页面 |
| 导出权限分层 | 当前全部已改密员工可导出；管理员专属规则尚未实现，需要业务决定 |
| 员工归属筛选、精确尺寸筛选 | 当前批量导出只支持日期、状态、配送方式、付款状态 |
| 商品数量统计 | 已有全库订单数、指定日新单数、当日待配送订单数；不是商品数量统计 |
| 地址智能校验 | 现有文本识别可提取地址标签内容，不进行地理编码或地址真实性校验 |
| 图片 OCR | 当前只做文本识别；不支持截图或手抄单 OCR、HEIC 上传 |
| 支付/配送集成 | 无支付渠道、流水、退款、第三方配送调度；记录付款方式文本不能自动标已付款 |
| 部分交付、多门店、独立排产 | 当前未实现，不列为已有功能回归失败 |
| 真实语料与生产环境验证 | 少量合成模型调用已验证；真实客户语料效果、实际账单、代理/TLS、容量及长期运行仍有未验证项 |

该表保留旧资料中仍有意义的边界与缺口，不承诺实施日期。发现新的业务需求时先确认范围，不能以旧 Slice 顺序或过时数据库草图直接实施。

## 保留的业务规则

- 一个订单是统一制作和交接单元，不支持部分商品先交付。商品支持逐项勾选完成，但没有独立的夹层、抹面或交接流程。
- 制作完成只表示备齐，不能自动确认客户收到。配送为待配送→配送中→完成，自提另行确认。
- 所有订单均须依次开始制作、完成夹层、完成抹面、确认“其他”，再完成整单制作，不能跳过节点。所有有效商品（含主蛋糕）逐项勾选完成后才能确认“其他”，完成整单制作时仍校验全部商品已完成。取消任一商品的完成勾选后，已确认的“其他”退回抹面完成。
- 制作与交付支持逐节点回退，已完成订单也可回退；待配送/待自提先退回“其他已确认”，再依次退回已抹面、已夹层、生胚中、待制作。普通回退保留商品勾选，退至待制作时清空整单制作阶段，并重置全部有效商品为未开始。已取消订单可恢复至待制作，执行同样重置，保留原订单号、业务资料、付款及历史活动。
- 付款与制作互不阻断。总额是与客户约定值，不按数量或商品报价自动重算；空金额与 0 元不同。
- buyerName 在界面显示为客户订购人，是向门店订购商品的客户，可留空；creditedEmployee 是独立的下单员工归属，用于员工业绩，创建/操作员工由服务器认证上下文决定。新单未传归属时使用当前员工，历史未归属不推定创建者；归档保留身份和昵称快照。
- plannedHandoffAt 在界面及订单单据中显示为取货时间，指客户自提或配送员从门店取走商品的时间；requestedReceiveDate 是日历归日。两者分别保存，不自动推定客户实际收到商品的时间。新建后返回工作台定位到订单的收货日期。
- 商品类型使用中文下拉框：蛋糕、甜甜圈、纸杯蛋糕、其他茶歇；分别保存 CAKE、DONUT、CUPCAKE、OTHER。历史特殊类型保持原值，改选时才更新。下拉框、日期和时分使用 React Aria Components；日期选定后收起，支持键盘分段输入。日期与时分完整后才组成取货／出品时刻，不自动补午夜。
- 奶油界面使用 attributes.flavor，内胚为 base，夹馅为 filling。蛋糕创建、追加、清空和缺失值读取统一使用原味内胚/芒果夹馅；显式选择优先，非蛋糕不套默认，读取兜底不写库。蛋糕尺寸只接受正数、最多两位小数、整数部分最多九位，保存为无单位数值文本；旧异常尺寸仍可读取。
- 日历首次为今天、全部状态和全部付款；按员工保存两个筛选偏好，损坏时回退全部。订单状态选项来自当前周／月原始订单，包含已夹层、已抹面、其他已确认，和卡片状态一致；成功读取后所选状态不存在时回到全部。单日列表包含完成/取消订单，筛选后再显示。
- 经营查询默认按本月录单日期（北京时间）查询，预约收货日期在未来的订单也包含；日期快捷查询仅保留今天录入，其他范围手动选择。查询/统计汇总导出最多 366 天，默认排除取消单（可明确包含或仅选取消），始终排除已删除订单；逐单 ZIP 使用完整已应用条件，最多 100 单、256 MiB。尺寸筛选累加匹配蛋糕 quantity，金额仍为整单约定金额，按手动付款标记分列、缺金额单独计数，不等于实收或提成结算。员工按账号合并、未归属独立保留。经营导出最多 10,000 单、50,000 行商品，不含图片，不静默截断。
- 查询与导出不新增业务日志。实际订单变化仍同事务留痕，历史 ORDER_EXPORTED 记录继续可读。
- 查询明细每页固定 10 条，订单号及“查看详情”进入详情；当前登录会话内返回查询保留筛选及页码。统计和导出始终覆盖全部匹配结果。
- 商品至少保留一件，移除保留历史。每件商品只展示自己的最近三条备注；详情备注区预览最近三条整单/商品备注，完整备注与操作日志在独立记录页分页查询，左上角返回详情。月历的日期及订单卡片进入当天工作台。
- 店长、前厅主管和前厅店员可查完整业务资料、经营统计、导出、删除及已删除记录；裱花主管、裱花师和烘焙师查看制作资料、客户手机号及所需时间，不能读取金额、完整客户信息或已删除订单。兼任岗位取并集，店长同时具有 SUPER_ADMIN，可管理员工并读取身份审计。
- 当前部署约定为单业务后端实例；SSE 没有跨实例广播或持久化重放，断线后通过 REST 补齐。

这些规则替代旧开发计划中的逐商品制作、两步录单、虚构独立任务聚合等草案。没有为旧计划预留通用工作流、支付、配送或制作任务模块。

## 尚未实现或尚待明确接受

| 项目 | 当前事实 |
| --- | --- |
| 独立身份审计页面 | 员工资料改动保留前后值，身份审计可经管理员 API 查询；无独立审计页面 |
| 地址真实性 | 支持标签与常见无标签收件信息提取；不进行地理编码、完整行政区划纠错或配送可达性校验，歧义仍需人工核对 |
| 图片 OCR | 当前只做文本识别；不支持截图或手抄单 OCR、HEIC 上传 |
| 支付/配送集成 | 无支付渠道、流水、退款、第三方配送调度；记录付款方式文本不能自动标已付款 |
| 部分交付、多门店、独立排产 | 当前未实现，不列为已有功能回归失败 |
| 真实语料与生产环境验证 | 少量合成模型调用已验证；真实客户语料效果、实际账单、代理/TLS、容量及长期运行仍有未验证项 |

该表保留旧资料中仍有意义的边界与缺口，不承诺实施日期。发现新的业务需求时先确认范围，不能以旧 Slice 顺序或过时数据库草图直接实施。

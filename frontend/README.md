# 午逅 Story 工作台（Slice C2-A / C2-B1d / C2-C1a / C2-C1b）

独立 React + TypeScript + Vite 前端。服务端数据使用 TanStack Query；没有新增后端领域模块、逐商品制作状态机或权限引擎。

## 本地运行

需要 Node.js 22.18+，以及已启动的 WuhouCake 后端、PostgreSQL 和 Redis。后端按仓库现有方式配置 RSA 密钥和员工账号。

```sh
cd frontend
npm ci
npm run dev
```

打开 `http://127.0.0.1:5173`。开发代理默认把 `/api` 原样转发到 `http://127.0.0.1:8080`；后端端口不同时：

```sh
API_PROXY_TARGET=http://127.0.0.1:18080 npm run dev
```

```sh
npm test
npm run build
```

`dist/` 为静态构建产物。生产应通过 HTTPS 在同一站点提供静态文件与 `/api` 反向代理；保留 Cookie、Authorization 和 SSE 流，不缓冲 `/api/orders/stream`，代理读超时应长于心跳间隔。`vite preview` 仅预览静态产物，不代替生产代理配置。本轮不部署。

内部试用只运行一个业务后端实例：SSE 连接和通知分发保存在进程内，没有跨实例广播或消息重放。代理应及时转发 15 秒心跳，保持连接；服务端流最长 5 分钟，客户端重连时重新读取 REST 数据。正式 HTTPS、Cookie 的 Secure 行为和实际代理超时须在试用站点验证。

## 页面与边界

- 工作台的「新建订单」进入 `#/orders/new`，默认带入选中收货日期和配送方式。客户电话、收货日期、计划交接时间、商品名称及配送地址必填；支持多个独立规格商品，至少保留一件。金额以元录入、整数分提交，空金额与零金额不同，订单总金额不按商品报价计算。计划出品对应 `plannedFinishAt`，时间按北京时间提交。
- 录单草稿仅存当前标签页内存，后台数据刷新不回填表单。返回、后退、退出和正常刷新／关闭有未保存提醒；确认离开后丢弃。认证失效后，同一员工重新登录可继续草稿及原日历位置；换员工或成功退出清除草稿。浏览器刷新、关闭后的草稿无法恢复，移动系统强制结束浏览器不能保证提醒。
- 创建成功后使用服务端返回的真实订单及商品标识，刷新相关缓存并进入详情，可继续现有付款、制作及交付操作。提交不自动重试；4xx 明确拒绝（408 除外）提示订单未创建。网络中断、请求超时、5xx 或无法解码的成功响应按结果未知处理，保留输入及提交时的日期、电话提示；核对入口在新标签页打开对应收货日期的工作台，不清除原草稿。修改草稿不会隐藏结果未知提示，换员工或离开录单页时清除。
- 登录、首次改密、会话恢复及退出。首次改密页显示当前工号，成功后清空密码、保留工号并提示使用新密码重新登录。Access token 仅驻留内存，刷新凭证沿用服务端 HttpOnly Cookie。认证 POST 前读取 CSRF Cookie；并发 401 共用一次刷新。
- 认证请求记住发起时的登录代次。退出或重新登录后，丢弃旧请求响应；旧 401 不借用新员工令牌重发，也不能清除新会话。原登录内的 JWT 刷新仍复用现有并发刷新机制。
- 周历与月历共用日期块，显示全部商品名称、订单状态和付款状态。以 `calendarDate`（后端按 `requestedReceiveDate` 投影）归日，`plannedHandoffAt` 只用于显示和排序。星期一为周起点，月历最多 42 格；切换周/月保留选中日期。手机横向滑动日期区域。
- 周历下方显示统计及所选日待办。统计直接使用服务端口径：总订单为全库数量，新下单按所选日创建时间统计，“当日需配送”仍读取 `deliveryDueOnDate`，表示所选日尚未完成/取消的配送订单。待办不含已完成、已取消订单，但这些订单仍能从日历进入详情。每个商品展示接口返回的最近三条商品备注，订单级备注不混入。
- `#/orders/{UUID}` 顶部并列呈现整单制作与交付、金额与付款，手机端先显示付款；每项业务操作只有一个入口，操作反馈显示在顶部。客户、全部有效商品、分页备注与日志依次在下方。进度只读取订单级 `status/currentStageCode`，区分配送与自提；跳过夹层/抹面时标为“未记录”，取消时显示流程终止。制作活动历史默认收起，可展开读取原有记录。动作按钮提交整单 API 和当前 `expectedVersion`，状态转换、金额与权限校验由后端决定。制作中可直接完成制作。
- 付款、制作、交付和取消成功后，用服务端返回的最新详情更新缓存，并等待相关查询刷新后恢复操作；旧版本响应不覆盖缓存中更高版本的详情。各动作独立提交，失败不撤销其他成功动作。409 重新获取状态并提示人工核对，不自动重试。
- 「客户与交付」的「编辑资料」在原区域编辑客户、交接安排及约定总金额；仅提供保存修改、取消，顶部付款入口保持唯一。所有订单状态均可更正资料；配送须有地址，自提可保留或清空地址。约定金额不按商品报价计算，也不改变付款状态。交接类型对应的订单状态由服务端返回结果决定，不自动触发制作或交付动作。
- 资料编辑从打开时的详情初始化独立草稿与版本，SSE 和查询刷新不回填输入。一次保存只 PATCH 实际修改字段；可选字段清空为 null，未改动不发送请求。金额复用整数分转换，空金额与零不同；UTC 时间显示为北京时间，未改的分钟输入不回写秒／微秒。收货日期和计划交接时间分别修改，保存沿用原有缓存刷新、日历迁日和修改日志。
- 资料修改发生 409 时保留草稿，刷新后在表单下方显示最新资料供核对；再次点击保存使用该次读取的版本，仅提交员工改过的字段，保留同事修改的其他资料。尚未获取新版本时保存禁用；再次出现并发修改仍返回 409，不自动重试。取消编辑恢复最新只读详情。返回、后退、退出及正常刷新／关闭对未保存资料给予离开提醒；草稿只在当前详情页面内存中保存。
- 「全部商品」在待制作、制作中提供单商品内联编辑、追加及一次确认的软移除；至少保留一件有效商品。待配送／待自提须先执行已有「重新制作」，配送中、已完成、已取消不提供商品修改入口。商品增减和报价修改不改变约定总金额或付款状态。
- 商品编辑仅 PATCH 稳定 itemId 的实际差异；常用文本规格按 attributes 顶层键提交，清空已有规格使用 null。未修改、未知、数组、对象和其他非文本规格保留原值；结构化规格只读展示。追加复用录单校验与元转整数分逻辑，商品标识取服务端响应。制作中追加按服务端结果清空整单节点；只有此前确有已确认节点且被清空时，成功文案才提示节点清空。修改和移除不主动清除节点。商品区变更提醒和商品操作成功提示只在待制作、制作中显示，进入交接或终止状态后停止显示；历史和独立最近备注完整保留。
- 同一详情仅保留一个资料或商品表单，后台更新不回填草稿，其他写入入口在编辑期间禁用。若编辑期间同事将订单推进到待交接，草稿保留，可执行已有「重新制作」；成功响应成为商品表单的保存基线，并显示最新商品供人工核对，员工点击保存后才提交原草稿。一般 SSE 刷新不提升保存版本。商品 409 保留输入并展示最新商品，员工再次保存才使用复核版本；保存前同事再次修改仍正常返回 409，不自动重试或覆盖其他字段。编辑中的商品被同事移除时仍保留草稿，禁止继续保存。追加网络失败、5xx 或无法解码的成功响应按结果未知处理，保留输入，先核对最新有效商品及日志，再决定是否重新保存。
- 详情写入期间阻止站内返回、后退、切换订单和退出，保存／取消及其他写入操作禁用；服务端响应写入缓存并等待必要查询刷新后恢复导航。资料和商品草稿沿用未保存离开确认；正常刷新／关闭由浏览器原生 beforeunload 提醒，浏览器允许用户确认离开，系统强制关闭无法保证请求完成。
- 创建订单后，在详情「全部商品」下方的「参考图片」添加 JPG/PNG：单入口选择文件、核对本地预览与整单／有效商品归属后确认上传。单图最多 5 MiB，每单最多保留 8 张。缩略图网格支持原生大图预览，显示真实归属、上传员工和时间；商品移除后的保留图标为「历史商品图片」。每图仅有一次确认的移除操作，释放额度并保留活动历史。
- 图片元数据独立使用 `['order', orderId, 'images']`，二进制经 `authenticatedFetch()` 携带 Bearer 并复用会话刷新，转换为组件持有的 Blob URL；不写入 JSON、订单详情缓存或 localStorage。每个图片 ID 在挂载期间只读取一次，预览复用同一 URL；移除、切换订单和卸载时中止请求并释放资源，迟到的响应不会回填其他订单。
- 图片表单与资料／商品编辑及其他写入互斥；上传和移除期间沿用现有站内离开与退出保护，不自动重试写请求。上传失败保留文件及归属；结果未知时提示先刷新图片列表、核对图片及历史，再决定是否重传。成功后清空选择并刷新本订单查询。`IMAGE_ADDED`、`IMAGE_REMOVED` 和 `ORDER_EXPORTED` 沿用修改日志，分别显示添加参考图片、移除参考图片、导出订单。
- 图片写入由组件持有 AbortController，卸载时取消并释放操作标记；迟到回调不能释放新页面的写入保护。待上传 File 只由组件和进行中的请求持有，不进入 MutationCache。详情其他写入回调也按页面生命周期隔离。取消客户端请求不能撤销已经提交的数据，重新登录后通过真实图片列表和活动核对结果。
- 备注与取消原因是独立本地输入状态，不从查询结果回填。后台刷新和 409 不覆盖输入；成功提交后才清空对应表单。成功提示可关闭，离开页面的草稿不持久化。
- 日历使用订单号，无手机号尾号扩展。采用附带午逅 logo 和参考图的黄色/浅色视觉语言；没有蛋糕照片字段时使用商品图标，不虚构商品照片。登录页为新增设计，不宣称参考图中存在登录页。

## 实时同步

每个已登录应用实例只在 `Workspace` 顶层创建一条 SSE 连接；页面组件不单独订阅。Fetch 携带 Bearer，`eventsource-parser` 处理分块、UTF-8、CRLF 和心跳注释。退出、卸载和 JWT 更新均先清理旧连接。

`order.changed` 使对应订单详情、活动及图片元数据查询、全部日历范围缓存和工作台缓存失效；当前挂载的查询立即重新获取，未挂载的查询在再次打开时读取新数据。所有通知都处理，不以 `version` 丢弃 NOTE、IMAGE_ADDED 或 IMAGE_REMOVED。迁日时重新获取当前完整范围，避免旧日期残留。

服务端没有消息重放：`ready`、JWT 更新、窗口恢复前台和网络恢复均重新同步 REST。连接失败指数退避至最多约 30 秒；45 秒未收到任何数据则主动断开并重连。数据请求透传 Query 的 AbortSignal，旧请求不会覆盖新结果。突发并发写入交给后端乐观锁；409 展示可操作的错误并重新获取，不自动重复业务动作。

## 验证

`npm test` 使用 Node 内置测试运行器，覆盖跨年/闰月的查询范围、同版本 NOTE、迁日后的范围失效、并发 401 单次刷新、SSE 分块解码、断线重连和单连接清理，以及录单金额精度、门店时间转换、多商品请求结构、创建异常分类和核对入口日期。资料编辑覆盖差异字段、可选值清空、UTC 初始化与时间精度保留、冲突复核后提交；商品编辑覆盖单商品差异、JSONB 保留、null 删除、金额转换、数量与最后一件限制和冲突草稿。真实浏览器验证过程与范围见 [verification.md](verification.md)。

实现参考：通过 Context7 核对 [React 状态保留](https://react.dev/learn/preserving-and-resetting-state)、[TanStack Query 查询失效](https://tanstack.com/query/latest/docs/framework/react/guides/query-invalidation)、[查询取消](https://tanstack.com/query/latest/docs/framework/react/guides/query-cancellation)、[业务响应更新缓存](https://tanstack.com/query/latest/docs/framework/react/guides/updates-from-mutation-responses)、[等待业务操作后的查询刷新](https://tanstack.com/query/latest/docs/framework/react/guides/invalidations-from-mutations)、[Vite 同源代理](https://vite.dev/config/server-options.html#server-proxy) 和 [eventsource-parser](https://github.com/rexxars/eventsource-parser)。

## 导出文件与日志

详情顶部「下载 XLSX」导出已保存的订单、有效商品、备注及有效参考图片；资料、商品或图片编辑期间禁用，避免将本地草稿误当成已保存内容。工作台「批量导出 ZIP」展开内联筛选区，默认选中日期；支持收货日期、订单状态、交接方式和付款状态。日期界面包含开始和结束当天，提交时将结束日期加一天，转换为后端 `[from,to)`。最多 42 天、100 张订单；未选择的业务条件不提交，未筛选状态时包含已完成和已取消订单。ZIP 内每单一份 XLSX，不新增页面或选择订单清单。

下载通过 `authenticatedFetch()` 携带 Bearer 并复用 401 会话刷新；解析服务端 Content-Disposition 的 UTF-8 文件名，收到完整且类型正确的二进制后，才用临时 Blob URL 交给浏览器下载。临时链接立即移除，URL 延后 1 秒释放；文件不存入 Query 缓存或 localStorage。提示仅表示已发起下载，员工须在浏览器下载记录中确认保存。

生成和接收文件期间禁用重复下载及当前表单操作，并沿用站内离开、退出和 beforeunload 保护。请求不自动重试；空结果、范围／数量超限及文件／正文过大的服务端 JSON 错误显示可理解的提示。网络中断、5xx 或文件响应异常时，文件可能已生成并记录活动，保留筛选值，提示先核对下载记录和订单日志，再决定是否重试。

ORDER_EXPORTED 沿用详情的分页修改日志，显示服务端员工、时间、单单／批量方式、含首尾的日期及业务筛选条件、导出时订单版本和图片数量。日志语义为文件生成并发起下载，不代表员工已保存；不提供历史文件重下载。当前员工导出结束后刷新相关活动查询，结果不确定时同样刷新。后端导出不发送 SSE，其他员工可点「刷新日志」读取最新记录，也沿用重新聚焦时的查询刷新。

本阶段只接入现有接口，没有新增后端行为或迁移。自动回归覆盖日期转换与 42 天边界、筛选请求、认证刷新、中文文件名、错误及不重试、临时下载资源释放和日志内容；真实浏览器与实际 XLSX／ZIP 文件检查见 [verification.md](verification.md#c2-c1b-订单文件下载与导出日志)。录单状态确认仍复用现有详情操作；保留 OrderItem 的 `productionStatus/currentStageCode` 类型，不据此渲染独立制作流程。

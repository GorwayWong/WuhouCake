# 午逅 Story 工作台

React + TypeScript + Vite，服务端数据使用 TanStack Query。员工共享登录/首次改密、日历工作台、新建订单、订单详情与记录、查询统计及导出；员工管理仅管理员可用。密码长度为 8–128 个字符。

## 本地运行

需要 Node.js 22.18+、已启动的后端/PostgreSQL/Redis，以及已初始化的员工账号。后端和密钥配置见[项目入口](../README.md#2-快速开始)、[账号说明](../docs/identity.md)。

~~~sh
cd frontend
npm ci
npm run dev
~~~

开发服务默认监听 0.0.0.0:5173，本机访问 http://127.0.0.1:5173，同一局域网访问 http://Mac局域网IP:5173；端口被占用时直接报错，不自动换端口，保持二维码地址一致。/api 代理到 http://127.0.0.1:8080；后端端口不同时设置 API_PROXY_TARGET，例如 API_PROXY_TARGET=http://127.0.0.1:18080 npm run dev。测试与构建为 npm test、npm run build，构建产物在 dist/。

下拉框、日期和时间输入使用 React Aria Components，统一中文、键盘操作和弹层定位，沿用本项目视觉样式。手机端选择项至少 48px 高，日历日期格 44px；星期一起算，选择日期后关闭，支持清空、今天和键盘输入。日期通过日历选择，小时与分钟分别下拉选择，支持 24 小时制及逐分钟选择，必须完整才形成 `YYYY-MM-DDTHH:mm`，不自动补午夜；业务请求继续按北京时间转换。自定义控件须显式传入写入期间的 `disabled`，错误定位通过 `focusFormField` 聚焦可见控件。

生产通过 HTTPS 同一站点提供静态文件和 /api 反向代理，保留 Cookie/Authorization，不缓冲 SSE。vite preview 仅预览静态产物。现有 Compose 运行后端和依赖，不自动构建或发布前端。当前仅支持单业务实例；代理超时、Secure Cookie 和真实手机需在部署站点验证。

## iPhone 主屏幕图标

Safari「添加到主屏幕」使用 `public/apple-touch-icon.png`（180 × 180 PNG），图案为白底煎蛋，默认名称为「午逅 Story」。图标链接和名称在 `index.html` 中声明，构建时图标复制到 `dist/` 根目录，须随前端静态文件一起发布；图标地址无需登录即可访问。

图标更新后，已有主屏幕入口可能继续使用 iOS 缓存。请删除旧入口，再用 Safari 打开站点并重新「添加到主屏幕」，核对预览图标和名称后添加。最终效果须在真实 iPhone 上验证。

## 录单与可选识别

手工录单支持多个商品，至少一件。“订单信息”先展示取货时间和出品时间，再填写姓名／电话、会员手机及地址。时间区域在 360px 及以上等宽并排，更窄屏幕上下排列；每项日期独占一行，小时和分钟在下一行并排，时分选择使用数字显示且保留完整的可访问名称。新建页不展示订购人姓名或交接方式选择器；地址必填，去掉首尾空格后恰好为“自提”时使用自提方式，其余内容使用配送方式。

新建页只填写一个合并后的时间（界面显示为“取货时间”）：日期必填、时刻选填，完整时刻同时提交到兼容接口的取货及旧收货字段，仅选日期时两个时刻均为 null。出品默认取货前一小时，可手动调整或恢复自动。日期按钮显示月日，弹出日历保留年月导航，保存包含完整年份；清除取货时刻仍保留日期。详情修改、客户扫码及员工核对统一使用取货与出品；客户自助填单仍需完整取货时间。金额以元输入、整数分提交，空值与 0 不同；约定总额独立于商品报价。时间按北京时间。

所有日期时间表单（含详情修改和客户扫码填单）的小时下拉只提供 07–22 时，分钟仍为 00–59 分。历史订单或识别带入的其他小时保留并显示为“原值”，可以保留或改选营业时段，不自动改写；非营业小时不作为普通可选项，接口和时间校验不新增营业时间限制。

顶部可展开客户下单信息识别。粘贴后点击一次识别并填充，将明确且合法的候选填入未保存草稿；不确定的姓名、名称、数量、时刻等留空。12000 字符上限超限保留输入，不静默截断；正文与订购须知分离，不从餐具、促销或可选口味取值。

- 逐字段显示 RULE/DEFAULT/MODEL、原文证据和待确认原因，允许修改候选后采用或直接编辑主表单。
- 已有人工输入（包括主动清空）不被覆盖，冲突须明确改用此值。已有手工商品先选择候选归属；重复识别同一原文复用绑定，不悄悄追加重复项。
- 撤销只还原本次识别写入且尚未再次手改的值，不复活已移除商品。
- 原文日期缺失、无年份或冲突时，清空未手改的日历初始日期；手改日期和地址保留。新建页识别到自提时将地址带入“自提”；识别到取货时间时带入唯一的取货输入，旧识别结果同时包含收货和取货时优先取货。交接方式与取货时间不作为隐藏字段单独提交。未知商品类型待人工确认，不能在创建时静默回落 CAKE。
- 奶油仍用 attributes.flavor；base 为内胚，filling 为夹馅。蛋糕内胚/夹馅空白和后台缺失时使用原味/芒果；非蛋糕不套默认。尺寸只填正数、最多两位小数，后台也校验。历史异常尺寸仍可查看，修改尺寸时须按数字填写。
- 员工手工新建订单自动归属当前登录员工，表单不再选择下单员工；更换录单员工须退出后重新登录。新建页不重复显示标题和返回链接，通过顶部“日历工作台”返回，未保存草稿仍有离开提醒。详情中可更正业绩归属，记录原值、新值和实际操作者；客户扫码填单确认仍显式选择归属员工，与客户侧订购人分开。
- 常见无标签姓名、电话和地址可提取；客服电话、门店地址不作为收件信息。自由文本姓名及多电话/多地址须复核，不承诺地址真实或可配送。
- 可选 AI 只补商品语义。员工查看实际片段并逐次同意后调用，结果仅为待确认建议；未启用、超时、限流、错误 JSON 不影响规则和手工录单。

识别不创建订单、不确认付款、不记业务活动。新建订单的原文及已带入字段的核对标记随本机草稿保存，不进入 Query 缓存；识别候选、撤销记录及第三方发送授权只在组件内存。取消、新轮次、卸载和换员工使旧响应失效。模型配置、数据范围、计费/保留风险见[订单模块](../WuhouCake-order/README.md#百炼配置)。

## 草稿、并发与异常

员工新建订单按账号保存至当前来源的 localStorage（`wuhou:order-draft:v1:<accountId>`），每个员工保留一份草稿，不设自动过期。表单和粘贴原文每次变化同步保存，切后台和 pagehide 补存；商品选择、原文展开状态、识别核对标记、手工修改保护及滚动位置一并保留，滚动保存节流 250ms。空白默认表单不保存。页面展示本机保存时间；存储不可用或空间不足时保留页面输入，明确提示保存失败并可重试。仅存储成功后才允许发送创建请求。

刷新、重开、离开后重入时弹窗选择“继续填写”或“放弃并新建”；关闭弹窗返回工作台且保留草稿。继续时使用草稿原取货日期，不用当前工作台日期覆盖。当前页面切后台后直接回来不询问。成功创建、明确放弃或主动退出清除草稿；主动退出需确认，登录自动过期及切换员工不删除原员工本机草稿。只有确认员工身份及录单权限后才读取或展示草稿，不保存登录凭证。账号隔离仅是应用展示边界，本机数据仍可被同源脚本或浏览器开发工具读取。

恢复时校验版本及嵌套结构；损坏或未知版本不会被默认值覆盖，必须明确放弃才删除。多标签页通过 storage 事件及写入前快照比对检测冲突，旧页暂停保存并要求重新载入，不合并草稿。草稿仅在相同设备、浏览器及来源内恢复；更换协议/域名/端口、清除网站数据或浏览器回收存储后无法恢复，不承诺绝对不丢失。

写请求不自动重试。每份录单草稿携带独立的 Idempotency-Key；创建响应不明时保留并锁定原提交内容，员工可手动“重试确认原订单”，重用相同内容与标识，返回原订单或完成原提交，不重复创建。确认后到详情修改；成功或放弃草稿后使用新标识。创建前先将原始载荷及结果待确认状态同步落盘，刷新恢复也使用原标识和原始载荷，不自动提交；明确拒绝后才解除锁定。放弃结果待确认的草稿或退出登录时，提示先核对工作台，删除本机草稿不会撤销已创建订单。追加、图片、导出遇网络中断、5xx 或无法解码的成功响应时，保留输入并先核对实际数据、活动或下载记录。

客户填单确认页展示同联系电话、同取货日期的全部待确认填单和正式订单，已确认填单不重复展示。取消单仅作历史参考，其余记录须明确核实为独立订单才可继续接单。勾选绑定服务端 `duplicateCheckToken`，轮询或确认时发现候选变化会取消勾选；`409 DUPLICATE_REVIEW_REQUIRED` 后读取最新记录重新核对。详情链接在新标签页打开，当前核对草稿保留。

资料和商品编辑从打开时详情初始化独立草稿及 expectedVersion，只提交实际差异。SSE 不覆盖输入或提升编辑基线；409 保留草稿并显示最新数据，员工复核后再提交差异。资料可清空的值用 null，商品未知/结构化规格保留。编辑商品被同事移除时仍保留草稿但禁止保存；待交接需先退回其他已确认，明确成功的回退响应更新编辑基线，原草稿保留并要求核对。

同一详情只开一个资料/商品/图片表单。写入期间禁用互斥操作、站内离开和退出，响应及必要缓存刷新完成后恢复。迟到响应按请求会话代次和页面生命周期隔离，不能污染新员工、其他订单或释放新操作的写入保护。备注及取消原因是独立本地输入，成功后才清空。

## 工作台、制作与付款

订单详情的“金额与付款”提供独立“修改金额”入口，需要金额读取及订单编辑权限。复用资料编辑的金额校验、草稿保护和版本复核，只提交整单约定总金额；留空为未报价、0 为零元，不改变付款状态或付款时间。取消订单按钮位于详情最底部，需要取消权限，展开填写原因后确认；完成及已取消订单不显示该按钮。

新增能力及正常操作截图见[客户填单与制作验证](../docs/verification/2026-10-23-customer-flow.md)。新建订单的固定套餐由客服保存当前商品清单；选择后批量带入，可改数量、内容和移除单品。套餐不预置客户资料或整单金额。商品统一为蛋糕、茶歇、饼干、小吃、饮品、现货面包甜点。只有蛋糕填写详细规格，其他商品仅名称、类型、数量及可选规格／特殊要求，员工报价仍可选填。旧分类归并后保留历史额外属性，普通编辑不删除隐藏字段。

订单查询默认收起筛选并保留快捷查询。“所有历史未付款”不限日期且按下单时间升序，包含已取消记录；高级筛选仍可展开。

周历分别标明“按出货日”的出货订单当前付款情况，以及“按付款时间”的当日付款订单；后者依据人工付款日期记录，非支付流水，出货日期不限。已付款出货订单缺少付款日期时显示待核对提醒，不计入付款标记日期统计，零条记录有专门说明。另有按出货日、尺寸、蛋糕胚口味统计的数量表。均不受下方订单／付款筛选影响；付款日期由系统记录，手动指定日期不在当前范围。

工作台默认周历，顶部保留“回到今天”和“新建订单”，不重复显示页面标题。日历工具栏只显示日期选择器及前后切换按钮；批量导出统一从“订单查询与统计”的“导出逐单 Excel ZIP”进入。过去日期仍有未完成交付的订单时，周历和月历同时标红并显示未完成数量，完成、取消、删除和付款状态不制造提醒；日期提醒不受列表筛选影响。

员工手工创建成功后进入取货日期的周历，订单及付款筛选重置为全部，自动展开并定位新订单。卡片以黄色背景及“刚刚创建”标记高亮，切换日期、离开日历、刷新或退出登录后清除；同一天切换周／月视图及后台刷新不重复定位。列表加载失败时仍显示创建成功提示，重试成功后再定位。仅改变创建成功后的导航，订单制作操作须主动打开详情。

周历为七列日期选择器，月历为固定高度的六周网格；星期一为周起点。取货日期归日，交接时刻按 Asia/Shanghai 显示和排序。日期概览反映全部订单，不受筛选影响；月历摘要为最早交货订单的首件产品和手机号后四位，多单显示省略标识。

周历及月历展开共用半小时分组时间轴，仅显示有订单的时段，未安排交接时间的订单列在最后的「时间待定」组。组内按准确交货时间、订单号排序；整张卡片进入详情。前台卡片标题显示首个商品名称，多商品追加“另有 N 项”；下方取货／出品时间左右两列（手机端也保持两列），再显示制作／付款状态和最新备注，移除独立数量统计行及电话、交接方式、订单号信息行。取货时刻缺失保留日期及“时刻待定”，出品时间缺失显示“待定”，不推算。最新备注取整单和所有有效商品中的最新一条（服务端按时间排序，同时间取较大备注 ID）。制作岗位继续使用原有缩略图、数量、信息和出品时间展示。待处理订单排在完成／取消之前，组内保留取货时间排序。每日统计在订单之后默认折叠；客户填单先显示核对队列，二维码管理默认折叠置后。

月历点击日期在该周下方展开，再点同日收起；同周切换内容，跨周移动面板。相邻月份日期在原月原位展开；月份箭头切月收起面板。仅周历或展开日期请求 workbench，缓存与实时刷新继续共用 calendar/workbench 查询键。

订单/付款筛选首次进入及刷新为全部，不读取或写入历史 localStorage；当前登录会话内切日期、周/月视图、详情往返保留筛选，切换员工或重新登录重置。订单状态选项来自当前范围，并保留当前已选状态；无匹配时不自动清除。状态名称和匹配沿用制作节点规则，包括“已夹层”“已抹面”；经营查询及导出仍使用后台正式状态。

日历 URL 保存日期、视图、显示月份和展开状态，例如 `#/?date=2026-10-21&view=month&month=2026-10&expanded=1`；旧 `#/?date=...` 仍进入周历。详情链接携带来源日历，显式返回及浏览器前进后退恢复原视图。直接打开详情时，返回该订单取货日期的周历。

具备完整经营查询权限的员工可在“订单查询与统计”按取货日期或北京时间录单日期（结束当天包含）、状态、付款、交接、尺寸、员工及订单号/客户/电话筛选。默认不含取消单，可选择包含或仅取消。尺寸和员工业绩按整个查询范围汇总，可点击分组查看订单；商品按 quantity 求和，尺寸组订单数分别去重。员工按账号合并，姓名显示最近录单快照。指定尺寸时仅累加该尺寸蛋糕，约定金额仍为整单金额。金额按手动付款标记分列，未填金额单独计数，不等于实收或提成结算。条件修改后须查询才生效，页面和经营导出共用已应用条件。最多查询 366 天，经营 XLSX 五张表最多 10,000 单、50,000 行商品，不含图片；旧单未归属不推定创建人。

订单明细固定每页 10 条，可通过页码或上一页／下一页翻页。订单号及每行“查看详情”均可打开订单；在当前登录会话内返回查询结果时保留筛选输入、已应用条件和页码，刷新页面或重新登录后重置。重新查询或选择统计分组回到第一页，结果减少时回退到有效末页。统计与经营导出始终覆盖全部匹配订单，不随明细页码改变。

“订单查询与统计”上方始终提供“清除筛选”：保留当前查询模式、日期范围和日期口径，清空其他条件并退出“所有历史未付款”，同步清除未提交的筛选输入、回到第一页并更新结果与导出条件。快捷日期查询仅提供“今天录入”；其他范围通过手动筛选查询。页面同时提供统计汇总 Excel 和按完整已应用条件生成的逐单 Excel ZIP，导出不受当前页码影响。

“已删除订单”模式按删除日期查询保留期内记录，默认最近 30 天；仅显示只读明细和逐单 ZIP，不展示经营统计或统计汇总导出。删除订单需原因及二次确认，所有状态均可删除；删除后不可恢复，30 天后永久清理。取消仍是长期保留的业务状态，不启动清理计时。权限和清理规则见[维护说明](../docs/order-maintenance.md)。

管理员的“员工管理”支持工号/姓名/状态/岗位查询、创建、编辑姓名与岗位、随机重置或指定密码及归档。指定密码带 expectedVersion，旧版本拒绝覆盖；成功撤销旧凭证并要求员工首次登录改密。工号固定；岗位与系统权限分开。初始密码仅在当前页面内存中展示，关闭后清除。编辑遇版本冲突保留草稿，重新查询核对。

详情顶部以制作摘要集中取货与出品时间、当前阶段和主操作、商品行备齐勾选、有效特殊要求及参考图入口；空要求不展示，详细资料继续保留。客户核对页可保存出品时间，确认接单后进入正式订单。

详情按整单展示制作与交付；所有有效商品（含主蛋糕）提供逐项完成勾选，所有订单均需经过夹层、抹面，全部商品勾选完成后确认“其他”，再完成整单制作。取消勾选或修改商品名称、类型、数量、规格会使对应商品确认失效，已确认“其他”时退回已抹面；价格修改不影响确认。旧在制订单须补齐确认，不自动补勾；已交付阶段及完成订单不批量回退。历史未记录制作节点的完成单显示未记录；制作完成后仍需配送/自提确认。付款独立双向更正，资料及商品变化不重算约定总额。每件商品保留自己的最近三条备注；详情备注区展示最近三条备注。操作记录与工作备注一样默认收起，展开显示最近三条，并保留“全部操作记录”入口。`#/orders/{id}/activities` 独立记录页按每页 20 条加载全部历史，支持 type 筛选及左上角返回。预览与历史查询 key 包含页大小，分页按活动 ID 去重；未发布备注离开时确认。备注发布遇网络或服务端异常时保留输入并暂停重发，先核对记录，确认未保存后点击“已核对未保存，允许重发”；明确的 4xx 拒绝（408 除外）可更正后直接提交。月历的日期和订单卡片进入对应日工作台，周历订单卡片进入详情。订单筛选固定提供完整订单状态与制作阶段，按当前显示状态精确匹配，不因日历范围内没有对应订单而隐藏。日历请求使用 `includeMetrics=false`，统计仅从当天筛选后的订单计算。

## 商品表单布局

员工录单、追加/编辑、客户扫码及核对、套餐编辑共用商品字段排布。商品类型位于商品标题区域；蛋糕依次为整行名称、规格（寸）与数量、蛋糕胚与夹馅、整行奶油、整行祝福语、整行特殊要求。360px 及以上成对字段为两列，更窄屏幕为单列；其他品类继续简表。时间与客户信息区域使用各自布局。

“规格（寸）”对应原 size，“蛋糕胚”对应原 base；不与非蛋糕的文字规格 specification 混用。各入口保留自己的必填、默认值和只读规格规则。套餐可留空，默认提示明确在下单时生效；带图商品视为已有内容，带入套餐只能追加，不能当空白行替换。字段容器与图片组件使用不同的 React sibling key，确保切换和识别回填后仅保留当前商品的一组控件，图片仍按原商品 UUID 关联。

新文字识别标题“规格（寸）／规格(寸)”与“尺寸／蛋糕尺寸”均写入 size；普通“规格：300ml”仍为文字规格，不根据尺寸猜测商品分类。界面错误定位按商品的新视觉顺序进行，分类错误定位到标题区，根字段保留原有校验顺序。

## 商品单价规则

CAKE 商品在录单、追加、编辑、客户填单核对及详情中不填写或展示普通单价和会员单价，其他商品两项价格继续选填。按商品类型判断，不按名称中是否出现“蛋糕”判断。纯蛋糕订单的金额区只保留整单约定金额；混合订单参考小计排除蛋糕，显示“其他商品普通价小计／会员价小计”，蛋糕不触发缺价或价格无效提示。整单约定金额始终独立填写。

改为蛋糕时清空草稿价格，再切回其他类型从空值填写。恢复历史草稿时隐藏蛋糕价格，保留结果待确认请求的原始载荷以支持原幂等键重试；识别、提交及服务端写入忽略蛋糕单价，不推算整单金额。历史数据库价格与审计保留，详情及导出隐藏价格；没有批量清理迁移。

## 图片和导出

员工新建页在“添加商品”旁提供“添加图片”，作用于当前商品，支持多选、缩略图及移除。每商品最多 5 张，取消整单 8 张限制；仅支持 JPG/PNG，单张 5 MiB、最长边 8192 像素、总像素 2400 万。图片按账号、草稿和稳定商品 UUID 存入 IndexedDB，刷新及恢复草稿后仍对应原商品；本地保存失败或文件缺失会提示，缺失图片须移除后重选。删除商品及放弃草稿清理未提交文件；识别替换暂留文件供撤销使用，最终随草稿清理。

有图订单创建后进入详情；先保存订单 ID 和待上传队列，再清理录单草稿。图片按稳定商品 ID 上传，每张携带独立 Idempotency-Key；失败图片在本机保留，刷新后可从对应商品重试，不重新建单或重复写图。成功上传后清理本地文件。订单详情图片随当前商品切换，历史未关联或已移除商品的图片单独展示；历史超额图片保留，少于 5 张后才可补传。读取、上传和删除继续依各自权限控制，客户扫码填单不增加图片上传。

服务端纠正方向并按最长边 1920 像素、JPEG 质量 0.80 处理，小图不放大，透明图保留 PNG；实际存储类型和文件名随输出同步。历史图片通过备份后的显式维护命令处理。

图片二进制经认证 Fetch 转 Blob URL，组件复用；移除、切换订单、卸载时取消请求并释放资源。File、Blob URL 和图片二进制不放入业务 JSON、Query/Mutation 缓存或 localStorage。

详情下载单单 XLSX；批量 ZIP 从“订单查询与统计”按已应用的查询条件导出，不受明细页码影响，最多 100 单。XLSX 只含有效商品、规定范围的备注和有效快照图片。

认证下载完整二进制并校验类型后，再创建临时链接；链接移除、Blob URL 延后释放。提示下载已发起，不表示员工已保存。导出不新增业务活动、不发 SSE、不改版本；历史 ORDER_EXPORTED 仍可读。完整额度与快照规则见[订单文件契约](../WuhouCake-order/README.md#图片与导出)。

## 实时与身份

每个 Workspace 仅一条 Bearer Fetch SSE，eventsource-parser 处理分块、UTF-8、CRLF 和心跳。ready、窗口/网络恢复和重连后重新读 REST；order.changed 失效相应订单详情、活动、图片、日历和工作台。NOTE/IMAGE 即使版本相同也处理。

站内“订单更新”显示本次在线期间最近 20 张订单的最新变化，包含本人操作，支持直接查看和全部已读；所点订单在当前页成功打开后才标为已读，取消跳转或在新标签打开不清除当前页提示；不持久化客户信息，账号切换/退出后清空。资料或商品编辑时发现新版本，保留输入并阻止保存，员工核对最新资料后明确继续，再按原始草稿的实际修改字段保存；服务端仍严格检查 expectedVersion，不自动重试写入。

失败指数退避至约 30 秒，45 秒无数据主动重连；退出、卸载、JWT 更新清理旧连接。后端凭证撤销后旧流停止，正常断开不写 JSON。没有事件重放或跨实例同步。身份恢复、401 单次刷新和 CSRF 契约见[账号文档](../docs/identity.md#浏览器认证)。

## 验证与边界

[验证摘要](verification.md)及[业务流程补齐验收](../docs/verification/2026-10-17-workflow-fixes.md)记录验证范围；[业务范围](../docs/product-scope.md)列出已实现与 GAP。地址真实性/配送可达性、图片 OCR、自动提成结算、支付和骑手调度未实现。

### 草稿回归验证

`npm test` 包含草稿存储、结构校验及提交载荷恢复测试；`npm run build` 检查类型及打包。

浏览器回归使用 `tests/orderDraft.browser.mjs`，通过 Playwright 拦截 API，在隔离浏览器中验证恢复弹窗、账号/权限、存储失败、多标签页及响应丢失后的同标识重试，不访问真实订单数据。先在 frontend 启动开发服务器：

```sh
npm run dev -- --host 127.0.0.1 --port 5197
```

另一个终端运行（需要可用的 Playwright 和本机 Chrome）：

```sh
node --test tests/orderDraft.browser.mjs
```

若 Playwright 不在当前 Node 模块解析路径，设置 `PLAYWRIGHT_MODULE` 为其绝对模块路径；可用 `DRAFT_TEST_URL` 指定开发服务器来源、`DRAFT_BROWSER_CHANNEL` 指定 Chromium 渠道、`DRAFT_SCREENSHOT` 指定手机宽度弹窗截图路径。测试使用 390×844 的 Chromium 视口，不能替代真实 iPhone Safari 下切微信、接电话、锁屏、关闭重开与系统回收后的验收。

### 取货与出品时间

页面只展示取货时间（客户或配送员从门店取走）和出品时间。出品默认取货前一小时，自动值随取货变化；手动调整后保持，可点“恢复自动计算”。草稿保存自动／手动模式；老草稿已有非空出品按手动值保留。识别明确给出出品时按手动安排处理，撤销识别恢复原模式，保留后续人工修改。已保存订单打开时不补值或保存。

历史取货优先 plannedHandoffAt，缺失回退 requestedReceiveAt／requestedReceiveDate；时间冲突在编辑核对区展示原值。只有新建或明确改取货才同步旧字段。客户扫码及核对仍要求完整时刻，员工可仅填日期。日历按取货日期，制作分组按出品时间并标明跨日日期。

### 前台订单详情

前台“订单信息”按三行两列展示名称／下单方式、取货／出品时间、客户／电话，下接地址、特殊要求、图片、下单时间。当前商品资料直接展开：数量／规格两列、蛋糕内胚／夹馅／奶油三列、非蛋糕价格／会员价两列。之后依次是整单付款、默认折叠的工作备注和补充资料。商品切换同步名称、特殊要求和图片，编辑、上传或导出期间禁止切换。制作岗位沿用现有详情。

员工新建、编辑及查询共用“下单方式”控件：下单人、小程序、到店、客服号，或“其他”填写最多 80 字符的具体方式；历史自由文本原样保留，实际文字及“其他”选择随本机新建草稿恢复。查询与两个导出接口均传递可选 `orderingMethod`，按完整文字筛选。详情浏览器回归在启动 Vite 后运行：

```sh
DRAFT_TEST_URL=http://127.0.0.1:5197 PLAYWRIGHT_MODULE=/path/to/playwright node --test tests/orderDetail.browser.mjs tests/itemImages.browser.mjs
```

`PLAYWRIGHT_MODULE` 替换为本机 Playwright 包路径。该回归覆盖 390px 和 1280px 布局、草稿恢复、字段编辑、多商品联动、折叠资料和制作岗位视图。

日历卡片浏览器回归在启动 Vite 后运行：

```sh
DRAFT_TEST_URL=http://127.0.0.1:5197 PLAYWRIGHT_MODULE=/path/to/playwright node --test tests/calendarCards.browser.mjs
```

覆盖 390px／1280px 两列时间、跨日与待定、名称精简、创建高亮、筛选及详情往返、付款权限和制作岗位原展示。

订单查询筛选支持双列布局和独立商品名称搜索，统计及导出口径见[订单查询筛选](../docs/order-query-filters.md)。启动 Vite 后运行浏览器回归：

```sh
DRAFT_TEST_URL=http://127.0.0.1:5197 PLAYWRIGHT_MODULE=/path/to/playwright node --test tests/managementFilters.browser.mjs
```

覆盖 320px 单列、360px／390px／1280px 双列、完整日期与弹层、组合查询、导出参数、分页及详情返回、清除筛选和历史未付款模式。浏览器使用合成数据；商品匹配和导出文件内容由后端 PostgreSQL 集成测试验证。

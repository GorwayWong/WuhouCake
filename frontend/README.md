# 午逅 Story 工作台

React + TypeScript + Vite，服务端数据使用 TanStack Query。员工共享登录/首次改密、日历工作台、新建订单、订单详情与记录、查询统计及导出；员工管理仅管理员可用。密码长度为 8–128 个字符。

## 本地运行

需要 Node.js 22.18+、已启动的后端/PostgreSQL/Redis，以及已初始化的员工账号。后端和密钥配置见[项目入口](../README.md#2-快速开始)、[账号说明](../docs/identity.md)。

~~~sh
cd frontend
npm ci
npm run dev
~~~

默认 http://127.0.0.1:5173，/api 代理到 http://127.0.0.1:8080；后端端口不同时设置 API_PROXY_TARGET，例如 API_PROXY_TARGET=http://127.0.0.1:18080 npm run dev。测试与构建为 npm test、npm run build，构建产物在 dist/。

下拉框、日期和时间输入使用 React Aria Components，统一中文、键盘操作和弹层定位，沿用本项目视觉样式。手机端选择项至少 48px 高，日历日期格 44px；星期一起算，选择日期后关闭，支持清空、今天和键盘输入。取货／出品的日期与时分分别输入，必须完整才形成 `YYYY-MM-DDTHH:mm`，不自动补午夜；业务请求继续按北京时间转换。自定义控件须显式传入写入期间的 `disabled`，错误定位通过 `focusFormField` 聚焦可见控件。

生产通过 HTTPS 同一站点提供静态文件和 /api 反向代理，保留 Cookie/Authorization，不缓冲 SSE。vite preview 仅预览静态产物。现有 Compose 运行后端和依赖，不自动构建或发布前端。当前仅支持单业务实例；代理超时、Secure Cookie 和真实手机需在部署站点验证。

## 录单与可选识别

手工录单支持多个商品，至少一件。电话、收货日期、计划交接时刻、名称、数量以及配送地址按现有校验填写；自提地址可空。金额以元输入、整数分提交，空值与 0 不同；约定总额独立于商品报价。时间按北京时间。

顶部可展开客户下单信息识别。粘贴后点击一次识别并填充，将明确且合法的候选填入未保存草稿；不确定的姓名、名称、数量、时刻等留空。12000 字符上限超限保留输入，不静默截断；正文与订购须知分离，不从餐具、促销或可选口味取值。

- 逐字段显示 RULE/DEFAULT/MODEL、原文证据和待确认原因，允许修改候选后采用或直接编辑主表单。
- 已有人工输入（包括主动清空）不被覆盖，冲突须明确改用此值。已有手工商品先选择候选归属；重复识别同一原文复用绑定，不悄悄追加重复项。
- 撤销只还原本次识别写入且尚未再次手改的值，不复活已移除商品。
- 原文日期缺失、无年份或冲突时，清空未手改的日历初始日期；手改日期、员工已选交接方式保留。未知商品类型待人工确认，不能在创建时静默回落 CAKE。
- 奶油仍用 attributes.flavor；base 为内胚，filling 为夹馅。蛋糕内胚/夹馅空白和后台缺失时使用原味/芒果；非蛋糕不套默认。尺寸只填正数、最多两位小数，后台也校验。历史异常尺寸仍可查看，修改尺寸时须按数字填写。
- 下单员工默认选当前员工，可选择其他在职员工；与客户侧下单人、实际创建员工分开。归属更改记录原值、新值和实际操作者。
- 常见无标签姓名、电话和地址可提取；客服电话、门店地址不作为收件信息。自由文本姓名及多电话/多地址须复核，不承诺地址真实或可配送。
- 可选 AI 只补商品语义。员工查看实际片段并逐次同意后调用，结果仅为待确认建议；未启用、超时、限流、错误 JSON 不影响规则和手工录单。

识别不创建订单、不确认付款、不记业务活动。原文/候选仅在当前组件内存，不进入 Query 缓存或 localStorage；取消、新轮次、卸载和换员工使旧响应失效。模型配置、数据范围、计费/保留风险见[订单模块](../WuhouCake-order/README.md#百炼配置)。

## 草稿、并发与异常

录单草稿只在当前标签页内存；后台刷新不回填。返回、后退、退出及正常刷新/关闭有未保存提醒，确认离开后丢弃。认证失效后同一员工重新登录可继续录单草稿；换员工、成功退出或创建成功清除。识别原文不承诺跨卸载恢复，系统强制关闭浏览器也不能保证提醒或恢复。

写请求不自动重试。每份录单草稿携带独立的 Idempotency-Key；创建响应不明时保留并锁定原提交内容，员工可手动“重试确认原订单”，重用相同内容与标识，返回原订单或完成原提交，不重复创建。确认后到详情修改；成功、放弃草稿或切换员工后使用新标识。草稿标识只在当前标签页内存，刷新或关闭后的新录单仍应先核对工作台。追加、图片、导出遇网络中断、5xx 或无法解码的成功响应时，保留输入并先核对实际数据、活动或下载记录。

客户填单确认页展示同联系电话、同收货日期的全部待确认填单和正式订单，已确认填单不重复展示。取消单仅作历史参考，其余记录须明确核实为独立订单才可继续接单。勾选绑定服务端 `duplicateCheckToken`，轮询或确认时发现候选变化会取消勾选；`409 DUPLICATE_REVIEW_REQUIRED` 后读取最新记录重新核对。详情链接在新标签页打开，当前核对草稿保留。

资料和商品编辑从打开时详情初始化独立草稿及 expectedVersion，只提交实际差异。SSE 不覆盖输入或提升编辑基线；409 保留草稿并显示最新数据，员工复核后再提交差异。资料可清空的值用 null，商品未知/结构化规格保留。编辑商品被同事移除时仍保留草稿但禁止保存；待交接需先重新制作，成功后保留原草稿并要求核对。

同一详情只开一个资料/商品/图片表单。写入期间禁用互斥操作、站内离开和退出，响应及必要缓存刷新完成后恢复。迟到响应按请求会话代次和页面生命周期隔离，不能污染新员工、其他订单或释放新操作的写入保护。备注及取消原因是独立本地输入，成功后才清空。

## 工作台、制作与付款

周/月历共用日期组件，星期一为周起点、月历最多 42 格；收货日期归日，交接时刻仅展示/排序。右上角筛选订单/付款状态，首次全部，按员工记住选择；非法偏好回退全部。当天列表含终态订单，并与日历使用相同筛选；指标为当天筛选单数、其中未付款/待配送单数。

工作台的订单状态选项从当前周／月历范围内的原始订单动态生成，不受已选状态和付款条件影响；名称和匹配规则与卡片一致，包括“已夹层”“已抹面”。“制作中”在工作台仅匹配尚未确认夹层／抹面节点的制作单；待自提等状态只有实际存在时显示。成功读取范围后，所选状态已不存在时清除该状态并记住“全部”；读取失败或进行中不重置。经营查询及导出仍使用后台正式订单状态，制作节点不作为后台枚举提交。

所有已改密员工可在“订单查询与统计”按收货日期或北京时间录单日期（结束当天包含）、状态、付款、交接、尺寸、员工及订单号/客户/电话筛选。默认不含取消单，可选择包含或仅取消。尺寸和员工业绩按整个查询范围汇总，可点击分组查看订单；商品按 quantity 求和，尺寸组订单数分别去重。员工按账号合并，姓名显示最近录单快照。指定尺寸时仅累加该尺寸蛋糕，约定金额仍为整单金额。金额按手动付款标记分列，未填金额单独计数，不等于实收或提成结算。条件修改后须查询才生效，页面和经营导出共用已应用条件。最多查询 366 天，经营 XLSX 五张表最多 10,000 单、50,000 行商品，不含图片；旧单未归属不推定创建人。

订单明细固定每页 10 条，可通过页码或上一页／下一页翻页。订单号及每行“查看详情”均可打开订单；在当前登录会话内返回查询结果时保留筛选输入、已应用条件和页码，刷新页面或重新登录后重置。重新查询或选择统计分组回到第一页，结果减少时回退到有效末页。统计与经营导出始终覆盖全部匹配订单，不随明细页码改变。

管理员的“员工管理”支持工号/姓名/状态/岗位查询、创建、编辑姓名与岗位、随机重置或指定密码及归档。指定密码带 expectedVersion，旧版本拒绝覆盖；成功撤销旧凭证并要求员工首次登录改密。工号固定；岗位与系统权限分开。初始密码仅在当前页面内存中展示，关闭后清除。编辑遇版本冲突保留草稿，重新查询核对。

详情按整单展示制作与交付，不渲染商品独立流程。未记录夹层/抹面的完成单显示未记录；制作完成后仍需配送/自提确认。付款独立双向更正，资料及商品变化不重算约定总额。每件商品保留自己的最近三条备注；详情备注区展示最近三条备注，`#/orders/{id}/activities` 独立记录页按每页 20 条加载全部历史，支持 type 筛选及左上角返回。预览与历史查询 key 包含页大小，分页按活动 ID 去重；未发布备注离开时确认。备注发布遇网络或服务端异常时保留输入并暂停重发，先核对记录，确认未保存后点击“已核对未保存，允许重发”；明确的 4xx 拒绝（408 除外）可更正后直接提交。月历的日期和订单卡片进入对应日工作台，周历订单卡片进入详情。日历请求使用 `includeMetrics=false`，统计仅从当天筛选后的订单计算。

## 图片和导出

创建后可添加整单或有效商品 JPG/PNG，单图 5 MiB、每单 8 张；HEIC/OCR 未实现。选择文件后先预览和核对归属，再确认上传。商品移除后的保留图片标为历史商品图片；软移除图片释放额度并保留活动。

图片二进制经认证 Fetch 转 Blob URL，组件复用；移除、切换订单、卸载时取消请求并释放资源。File、Blob URL 和图片二进制不放入业务 JSON、Query/Mutation 缓存或 localStorage。

详情下载单单 XLSX；工作台批量 ZIP 支持日期、状态、交接方式、付款。界面结束日期包含当天，提交先加一天转为 [from,to)。最多 42 天/100 单，超量提示，包含完成/取消单；当前普通员工也可导出。XLSX 只含有效商品、规定范围的备注和有效快照图片。

认证下载完整二进制并校验类型后，再创建临时链接；链接移除、Blob URL 延后释放。提示下载已发起，不表示员工已保存。导出不新增业务活动、不发 SSE、不改版本；历史 ORDER_EXPORTED 仍可读。完整额度与快照规则见[订单文件契约](../WuhouCake-order/README.md#图片与导出)。

## 实时与身份

每个 Workspace 仅一条 Bearer Fetch SSE，eventsource-parser 处理分块、UTF-8、CRLF 和心跳。ready、窗口/网络恢复和重连后重新读 REST；order.changed 失效相应订单详情、活动、图片、日历和工作台。NOTE/IMAGE 即使版本相同也处理。

站内“订单更新”显示本次在线期间最近 20 张订单的最新变化，包含本人操作，支持直接查看和全部已读；所点订单在当前页成功打开后才标为已读，取消跳转或在新标签打开不清除当前页提示；不持久化客户信息，账号切换/退出后清空。资料或商品编辑时发现新版本，保留输入并阻止保存，员工核对最新资料后明确继续，再按原始草稿的实际修改字段保存；服务端仍严格检查 expectedVersion，不自动重试写入。

失败指数退避至约 30 秒，45 秒无数据主动重连；退出、卸载、JWT 更新清理旧连接。后端凭证撤销后旧流停止，正常断开不写 JSON。没有事件重放或跨实例同步。身份恢复、401 单次刷新和 CSRF 契约见[账号文档](../docs/identity.md#浏览器认证)。
